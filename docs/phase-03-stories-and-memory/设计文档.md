## 1. 目标与约束

把"赴约识别 → 出行衔接 → 单/多人故事 → 记忆回写 → 回到聊天"实现为一组**显式、可中断、可恢复的状态**，而不是让模型现编整场约会。复用现有生成、世界书、宏、流式与聊天存储，不改角色卡/世界书文件格式，不引入导航库。

**当前状态：计划，尚未实现。** 仓库中没有 story/outing 相关模块、数据或界面代码；下文"新增/计划"均未落地，数据字段是设计草案而非已定 schema，本设计不构成"已实现"证据。

### 1.1 硬约束

| 约束 | 内容 | 依据 |
| --- | --- | --- |
| 依赖方向 | `app → feature → domain/core`，`data:*` 提供实现；`feature` 只依赖 `core/domain`，`domain` 不依赖 android/androidx；新增模块须同步 `settings.gradle.kts` 与 `checkArchitecture`。 | 根 `build.gradle.kts` 的层规则 |
| 不新建导航库 | 页面用现有 `ChatDestination` 枚举 + `ChatDestinationHost` 分支 + 返回栈；故事状态从存储重建，不放 Bundle。 | app/ui/chat/ChatNavigationState.kt、ChatDestinationHost.kt |
| 线上纯消息 | 故事旁白/动作不得进入聊天消息正文；聊天只追加角色实际发送的消息。 | 需求 §4；阶段 1 纯消息规则 |
| 唯一会话 / 禁止快穿 | 一个 `charFile` 只有一个 `ChatSession`；故事未结束时不能切换世界，离开页面或重开 APP 不解除。 | 需求 R3-15、R3-22、R3-23、P3-11 |
| Room 基线 | 消息表 `(sessionId, ts)` 为主键；若必须改 schema，按 v9 基线注册显式 Migration、提交 schema 快照与旧库升级测试，禁止 destructive。 | 仓库工程约定 |
| 不污染 ST 格式 | 故事/记忆不写角色卡 JSON 与世界书文件，导出保持兼容。 | 阶段 1 数据层约定 |

## 3. 数据模型与存储

### 3.1 存储位置

| 数据 | 位置（计划） | 说明 |
| --- | --- | --- |
| 故事会话 + 索引 | `filesDir/stories/<storyId>.json`、`stories/index.json` | 每场一个文档、回合级原子落盘；索引可删后扫描重建。 |
| 角色记忆 | `filesDir/memories/<charFile>.json`（待定） | 按角色隔离；也可并入故事文档，二选一待定（§9）。 |
| 地点 | 不单独存 | 进入故事时对阶段 2 地点数据做快照；世界书仍是地点事实来源。 |

不新增 Room 表：故事消息与聊天展示形态不同（旁白、多角色、选项），JSON 可避开 v9 基线后的显式迁移成本；若最终入 Room，必须按 §1.2 补齐迁移。

### 3.2 故事会话与回合（计划）

| 字段 | 说明 | 状态 |
| --- | --- | --- |
| `storyId` / `turnId` / `sessionId` | 场次、回合幂等 ID 与回写目标会话（唯一会话）；重复提交同回合不重复落盘。 | 定 |
| `worldId` / `participants` / `placeSnapshot` | 所属世界、参与 `charFile` 列表；`{id,name,tags,summary}` 快照防世界书后续编辑改掉当场环境（字段以阶段 2 地点结构为准）。 | 定 / 快照字段待定 |
| `status` / `startedAt` / `savedAt` / `summaryId` | `ONGOING/PAUSED/FINISHED`；真实时间戳，游戏时间由阶段 2 提供；结束后摘要引用。 | 定 |
| `turn` / `stateFacts` / `currentOptions` | 回合数；必须遵守的事实短句；当前待选行动（可重建，不当作已发生）。 | 定 |
| `messages[]` | `{turnId, narration, actorLines[{charFile,text,action?}], userText, presentCharFiles}`；旁白不标为角色发言，`presentCharFiles` 决定谁写入知情记忆。 | 定 |

### 3.3 赴约入口 OutingIntent（计划）

| 字段 | 说明 | 状态 |
| --- | --- | --- |
| `intentId` / `charFiles` / `placeRef` / `storyId` | 赴约标识、涉及角色、目标地点；进入故事后回填 `storyId`。 | 定 |
| `sourceMessageTs` | 触发按钮的聊天气泡时间戳（反查上下文）。 | 待定：写回方式未确认 |
| `status` | 最小集 `PROPOSED → ACCEPTED → TRAVELING → IN_STORY → ENDED`；`MISSED/CANCELLED` 待定。 | 待定：当前需求只确认用户点击路径 |

历史方案的角色发起、改约、冷却、到点提醒、错过补算超出当前需求，差异见 [调研文档 §4](调研文档.md)；阶段 3 先做"用户点击 → 出行 → 进入故事"，其余随阶段 4 确认。

### 3.4 角色记忆与结束摘要（计划）

| 字段 | 说明 | 状态 |
| --- | --- | --- |
| `charFile` / `facts[]` | 记忆按角色隔离；每条 `{factId, text, storyId, kind, knownAt}`。 | 定 |
| `kind` / `witnesses` / `source` | `participated/witnessed/told`；写入时在场角色集合，防越界复述；来源为线上约定/线下事件/摘要。 | 待定：需求只明确"知情" |
| `OutingSummary` | `{storyId,title,placeName,highlights,memoryLine,promiseNext,endedAt,endReason}`：只从已提交回合提取，失败模板兜底。 | 定 |

记忆读取按 `charFile` 查询，只把该角色已知事实注入其上下文，未参与角色不得读到（P3-09 核心不变量）。摘要只写记忆，**是否回写 1–3 条聊天消息待确认**（与纯消息边界冲突，见 [需求文档 §7.2](需求文档.md)）。

### 3.5 与 Room 消息、世界书地点数据的关系

| 对象 | 关系 |
| --- | --- |
| Room `messages` | 故事回合不进消息表；结束后如需回写，只能追加普通 `assistant` 消息（正文合法、`ts` 严格递增），不得用消息正文承载旁白/动作。 |
| `ChatSession` | 故事通过 `charFile` 关联唯一会话；不新建会话、不复制聊天历史；会话级 `extState`/`timedWi` 不用于故事状态。 |
| 世界书地点 / 阶段 2 时间与位置 | 只读：阶段 2 解析出地点/路线后进入故事时取快照，故事不修改世界书文件与条目合并规则；游戏时间、用户与角色位置由阶段 2 单一状态源提供，故事内时间推进与"离开页面"不改世界时间。 |

## 4. 接口与关键流程

### 4.1 赴约识别 → 移动 → 进入故事（计划）

1. 聊天生成完成后按规则/模型标记识别线下意图（**判定方式待定**），在消息上提供赴约按钮（地点 + 角色），不自动执行；用户点击后若跨地点，调用阶段 2 出行流程（出行方式、路上状态、推进游戏时间）。
3. 到达后检查角色位置、日程与是否同场景；满足才可开始故事，不满足给出可解释结果。
4. 创建 `StorySession`（开场旁白 + 参与角色 + 地点快照），登记 `StoryPresence`，进入 `ChatDestination.Story(storyId)`；随即生效"暂停同场景聊天回复"与"禁止快穿"。

### 4.2 回合管线（计划）

```text
用户行动（选项 / 自由输入）
→ [domain:story] 意图解析（选项类型；自由输入→对话/行动/结束，失败兜底为对话）
→ [domain:story] 状态推进（turn+1、stateFacts 增量、presentCharFiles）
→ [domain:story] beat 选择（saliency：条件最具体 → 最久未用 → 随机；可为空 = 自由回合）
→ [feature/app] Prompt 组装（角色卡/预设/世界书 + 场景块 + 事实清单 + 导演指令 + 最近 N 回合）
→ [domain:generation] 流式生成（正文 + 末尾选项块）→ [domain:story] 解析 2–4 选项（失败则无选项，不报错）
→ 结束判定 → [data:story] 原子落盘（幂等 turnId）→ 显示叙事与选项
```

生成失败或中断不写半截回合：回滚到输入前，`turnId` 不变，允许重试。

### 4.3 多人参与与知情范围（计划）

- 参与者只能由阶段 2 的位置/日程/同场景判定产生，用户不能凭空拉人入场景。
- 一回合输出需区分旁白与各角色台词/动作：**生成方式待定**（一次生成多角色结构化输出 vs 逐角色生成再合并）；首版可让模型输出带角色标注的段落，解析失败退化为单角色叙述。
- 每回合记录 `presentCharFiles`，只有在场者写入该事件记忆。发言顺序/抢话不在本阶段确认范围。

### 4.4 记忆读写（计划）

- **写**：故事结束 → `OutingSummary` → 按 `participants` 写入各自记忆（事实 + 摘要引用），同 `storyId` 幂等不重复；**读**：生成聊天/故事上下文时按目标 `charFile` 取相关记忆（近期 + 关键词命中），作为独立提示块注入，不混入其他角色记忆。
- **复用边界**：现有摘要扩展是会话级（`ChatSession.extState` + 历史跳过），故事事件不在消息表里；计划新增按角色的记忆存储与注入入口，注入形式待定。

### 4.5 故事结束、禁止快穿与恢复（计划）

| 结束方式 | 触发 | 处理 |
| --- | --- | --- |
| 用户结束 / 事件完成 | 故事页"结束故事" / beat 标记结束 | 可先生成道别 → 摘要 → 回写 → 解除限制 |
| 时长/回合上限 | 阶段规则（待定） | 收尾 → 摘要 |
| 离开页面 | 返回 / 切后台 | **不是结束**：存 `PAUSED`，保留 `StoryPresence`。 |

状态门闩：世界切换入口读到 `StoryPresence` 非空即阻止并提示先结束故事；聊天回复调度读到角色在 `StoryPresence.charFiles` 即暂停该角色聊天回复；阶段 4 主动消息复用同一门闩。门闩必须持久化（随故事文档 + 可重建索引），APP 启动/恢复时按 `ONGOING/PAUSED` 重建，重开 APP 不能绕过限制。

每回合提交即恢复点：故事页从 `data:story` 重建消息、`currentOptions` 与 `turnId`，进程被杀最多丢当前未完成回合；恢复前重新校验世界/位置/日程，状态已变化时的处理待定。

## 8. 风险、限制与技术债

| 项 | 影响 | 缓解 |
| --- | --- | --- |
| Prompt 装配在 `:feature:chat`（代码事实） | 场景不能直接复用，复制会漂移并破坏 ST 兼容 | 先下沉通用装配或新增 `:domain:generation` 场景装配入口，再写故事生成；禁止复制 `PromptBuilder`/世界书激活逻辑。 |
| 多人同场无群聊基础、生成链路是单角色 | 多人输出可能相互矛盾、发言不可辨认 | 首版限制参与者数量与发言结构；生成方案先验证再定（见调研文档待调研）。 |
| 知情范围靠"在场集合"、摘要扩展是会话级 | 漏写/多写直接违反 P3-09；故事经历进不了现摘要 | 记忆写入只由 domain 规则决定，模型不直接写记忆；独立记忆存储 + 注入入口，不改扩展语义；单测覆盖未在场角色。 |
| 回写聊天与纯消息边界 | 回忆卡/旁白可能泄漏到线上 | 只允许普通消息正文；回写形态待产品确认。 |
