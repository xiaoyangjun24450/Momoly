# 请求情况

更新：2026-11-08。面向初次接手的开发者，按当前源码记录角色与聊天的模型调用；不是全 App 网络流量清单。请求内容见[请求包内容](请求包内容.html)。一次“逻辑调用”可能因备用模型尝试而产生多次网络请求；流式返回的多个文字片段不算多次调用。

提交 `f72cfab` 已移除重新生成回复、压缩聊天摘要、生成聊天标题；2026-11-08 再按当前源码移除通信状态造成的暂缓请求和短回复限制。下表只列当前仍保留的请求情况。

## 触发情况表

| 情况 | 发起条件 | 请求作用与次数 |
| --- | --- | --- |
| 角色回复用户 | 角色含 `life` 配置；用户消息先保存，`pendingInput > answeredInput`；通常等待输入收集时间 `inputReadyAt`（最后一次提交后 3 秒），且消息游戏时间已到；不检查忙闲或移动状态 | `respond` 生成正文和状态建议，通常 1 次。正常分段发布，不再限制为一段、240 字符；空回复报错并保留待答，通用输出长度保护仍生效 |
| 角色主动联系 | `nextContact <= world.now`，且通过当前主动联系系数的确定性概率筛选；不检查通信状态。同一角色若有已到游戏时间的待答消息，优先回复，不受该系数阻挡 | 筛选跳过则不调用模型；通过后调用 `respond`，模型仍可返回 `messages=[]`，所以没有新气泡也可能已调用、计费 |
| 重开或切回世界后补齐 | 当前世界的 `now < target`；本地逐步推进，遇到到期的待答或联系机会时调用 | 复用上面两种请求，不是单独的“离线总结”。连续处理达到 12 次事件且仍积压超过 60 游戏分钟时暂停，需继续；不是每日上限 |
| 补做状态整理 | 主回复不能解析为 `LifeTurn`，去掉代码围栏后非空，且不以 `{` 或 `[` 开头 | `assessPlainReply` 再调用 1 次，提取状态变化；坏 JSON、空正文不会走此兜底。整理失败则不发布候选正文 |
| 普通聊天生成 | 发送入口未被世界运行器接管（例如无 `life`）；消息保存并经发送调度后进入 `ChatGenerationRunner` | 通常 1 次；本分支不执行角色生活的状态核对协议 |
| 工具调用后的续答 | 普通生成启用了工具且有执行器，模型返回工具调用 | 执行搜索等工具后，将结果再交给模型；最多正常执行 3 轮工具，之后回传拒绝信息，最多发起 6 轮模型请求（含首次）。角色生活请求的应用函数工具列表为空，不走此循环 |
| 内嵌前端或扩展调用 | 内嵌页面显式调用生成桥接，或已启用扩展在自身逻辑中调用 `services.callModel` | 按调用方提供的消息请求；不是自动复制整套角色上下文，次数取决于调用方 |
| 失败后尝试备用模型 | `allowFallback=true`，尚未输出正文/思考，且发生网关允许继续尝试的请求/网络/空结果错误 | 换其他已启用、同任务类型的模型再发。角色生活的两类调用允许；普通生成仅首轮允许；已输出、取消或停止时不切换 |

## 调度边界

- 世界运行器只在 App 前台、未暂停时处理当前世界；进入后台、停止或切世界会取消在途工作。不是关闭 App 后持续请求，也不请求未选中世界的角色。
- 世界角色的新消息若遇到超过 5 游戏分钟积压，保留输入框内容，先补齐；不是立即保存并请求。无可用模型或关联资源读取失败时，保留进度并报错。
- 条件按代码分两步：`step` 用“待答已就绪 **或** 联系时间到”选角色，`respond` 再判断是否有到时待答。因此联系时间已到时，可能在 3 秒收集窗口结束前按回复处理；3 秒不是绝对门槛。
- 首次注册的联系时间为 `world.now + 30 分钟`；后续按话多程度、好感、确定性偏移计算基础间隔，再除以主动联系系数（0.05—1）拉长间隔；基础至少 25 分钟。日程或移动不再阻挡请求，也不再因不可通信顺延联系检查。
- 等待从需要回应的消息实际写入聊天并确认发件箱时开始，历史补发使用投递时世界目标时间。用户消息保存成功立即结束等待，阅读不算回复。追加联系不重置起点。
- 本地时间推进独立计算超期焦虑、烦躁、好感损失和回复后的渐进恢复，保存结算游标；不调用模型，不依赖是否发出消息。人物参数初始化、离开情况和互动修复建议沿用生活主请求或纯正文补整理，不增加专门请求。
- 本地时钟、日程移动、模拟天气、情绪衰减、存档、世界书筛选和查看资料本身不调用模型；推进碰到联系/待答条件且通过上述条件时才调用。插话或失败后继续处理仍属上表，不恢复使用已经过期的结果。
- 翻译、图片生成、在线朗读、搜索服务、模型列表和连接测试属于其他网络入口；不能用本表断言整个 App 仅有这些请求。

## 已移除的请求

| 功能 | 当前行为 |
| --- | --- |
| 重新生成回复 | 已删除重答入口和生成分支，不再对已有回复发起重生成请求。切换备选开场白或已有消息版本仍可用，只读取本地内容 |
| 压缩聊天摘要 | 已删除内置摘要扩展及设置，回复完成后不再自动请求压缩摘要；旧启用配置不会恢复该功能。旧摘要不再参与请求，历史处理见[请求包内容的容量与记忆边界](请求包内容.html#容量与记忆边界) |
| 生成聊天标题 | 已删除自动生成、手动重新生成及对应模型设置；即使会话标题为空，回复完成后也不会请求生成标题。已保存的标题保留 |

这里移除的是三项内置功能。普通发送、角色生活处理、工具续答和扩展自行调用模型仍可能发请求，不能理解为“每条消息固定只请求一次”。阶段 3 的角色记忆仍属待实现目标，不由旧摘要扩展提供。
