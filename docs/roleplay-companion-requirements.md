# 角色扮演情感陪伴 APP 需求

更新日期：2026-11-01  
状态：业务需求已整理；角色卡与世界书的最低内容清单和具体字段校验规则待后续调研。

## 1. 产品定位

将当前项目做成以角色扮演和情感陪伴为核心的 APP，结合类似微信的即时聊天与文字游戏／交互小说式的线下互动。

角色拥有持续的记忆、所处地点和自己的日程，会主动联系用户。线上聊天与线下互动共同构成一段持续发展的关系。

角色根据世界书归入不同世界。用户可以在世界之间快穿，同一时间只有用户所在的世界运行，其他世界的时间和角色活动全部冻结。

## 2. 已确认需求

### 2.1 角色导入与通讯录

- 支持导入 PNG 角色卡，读取角色信息及其附带的世界书。
- 导入时进行格式校验；世界书缺失或没有名称时，格式校验不通过，不能导入。
- 角色卡与世界书的最低内容清单、必填字段、数据结构及具体关联校验规则先不写死，列入 [格式校验待调研事项](roleplay-companion-plan/character-card-import-spec.md)。产品需要使用的信息不直接等同于导入文件必须显式携带的字段。
- 校验失败时说明具体问题，不部分添加联系人或世界数据；具体校验范围依据后续调研补充。
- 角色卡提供角色的身份、性格、背景等设定；世界书提供相关世界设定，包括固定的地点和场景。
- “加好友”就是将导入角色卡包装为添加通讯录的交互；导入成功后，角色成为通讯录中的联系人。
- 每个角色只有一个持续存在的聊天会话，聊天记录、关系和记忆长期延续。

### 2.2 世界分组与角色归属

- 根据角色卡附带的世界书名称确定角色所属世界，同名世界书对应同一个世界，好友列表按世界分组。
- 导入时已有同名世界则加入该世界；没有对应世界则创建新世界。
- 加入已有世界时，合并世界书条目：名称不同的条目追加，同名条目保留已有的旧条目，不用新条目覆盖。
- 一个角色只能属于一个世界，并且始终只有一个聊天会话。
- 世界管理所属角色、公共地点和场景；同一世界中的角色共用这些地点和场景。
- 角色各自保留身份、性格、背景、日程和记忆。属于同一世界不代表自动互相认识或共享私人记忆。

### 2.3 世界切换、冻结与恢复

- 用户在世界之间直接切换，采用“快穿”形式，无需移动等待。
- 同一时间只有用户当前所在的世界运行；该世界按游戏内时间推进，角色按日程活动、移动和回复消息，也可以主动联系用户。
- 其他世界的时间、角色日程、移动及其他活动全部暂停，角色不会主动发消息或回复聊天。
- 冻结规则始终适用，不仅限于用户进行线下互动时。
- 切换世界时，原世界冻结，目标世界恢复。
- 再次返回某个世界时，从离开时冻结的时间和状态继续，保留原有记忆与故事进度；离开期间该世界不推进时间或角色活动。
- 线下故事进行期间禁止切换世界，必须先结束当前故事才能快穿；单角色和多人线下故事遵守同一规则。

### 2.4 地点、移动与时间

- 世界书中包含家里、教室、图书馆等固定地点和场景。
- 不同地点之间的基础移动耗时由世界书提供。
- 用户可以选择当前所在的地点，并前往其他地点。
- 用户可以选择出行方式，出行所需时间结合世界书中的移动信息确定。
- 同一世界内，从一个地点移动到另一个地点需要消耗一定的游戏内时间，不能不消耗时间就到达；世界之间的快穿不受此移动耗时规则限制。
- 移动过程中显示“路上”或“前往某处中”等状态，到达后才进入目标场景。
- 用户在路上时可以继续与当前世界的角色聊天，角色是否回复仍受其日程和状态约束。
- 系统需要记录用户和角色的位置及相关状态，使见面、聊天和线下互动保持一致。
- 时间采用游戏内时间推进，用户可以选择加速推进多久的游戏内时间。
- 加速推进作用于当前世界，其移动进度、角色日程和活动随游戏内时间推进；其他世界继续冻结。
- 后续扩展地点时，由 agent 生成新地点及相关出行信息，包括与已有地点之间的移动耗时和可用出行方式。

### 2.5 角色日程与可互动状态

- 当前世界的角色会根据自己的日程移动，拥有随该世界时间变化的位置与活动状态；其他世界的角色保持冻结。
- 角色日程影响用户是否能与其见面，以及角色何时回复消息。
- 角色回复需要结合当前活动和状态，不能默认始终即时回复。
- 角色的位置、日程和正在进行的互动需要保持一致，避免同一角色同时出现在互相冲突的场景中。

### 2.6 类似微信的线上聊天

- 聊天 UI 采用类似微信的形式，包括好友列表、会话列表和消息气泡。
- 聊天内容需要有活人感：使用线上聊天预设，结合角色性格、起始关系和上下文形成自然口吻，避免固定客服模板、机械复述、无必要的长篇说教和每轮固定追问。
- 线上角色回复只展示实际发给用户的消息正文，不包含动作描写、场景描写、旁白、内心独白或小说式段落。角色以普通消息汇报已知状态、表达情绪可以保留；面对面行为与场景叙述在线下故事中呈现。
- 开场白、备选开场白、普通回复、重新生成和主动消息都遵守纯消息规则。角色卡或关联预设中的叙事要求不能覆盖线上输出约束，不合格内容不能作为最终消息发布。
- 当聊天中出现见面、一起吃饭、去图书馆等线下行为意图时，提供明确的交互按钮，例如“赴约”或“前往图书馆”。
- 用户点击按钮后进入相应流程；涉及跨地点移动时，需要先完成移动，再进入目标场景的线下互动。
- 每个角色始终使用同一个聊天会话，不因地点或线上、线下模式切换而新建会话。
- 聊天消息受世界运行状态约束：只有当前世界的角色能够发消息或回复，其他世界的角色保持冻结。
- 用户处于“路上”状态时，仍可在聊天界面收发消息。

### 2.7 文字游戏／交互小说式的线下互动

- 线下互动使用独立界面，呈现场景描述、角色动作、面对面对话和用户行动。
- 用户通过选项推进故事，也可以自由输入行动，两种方式结合使用。
- 支持同一世界的多个角色同时参与一段线下故事，并区分各角色的发言、动作及各自获知的信息。
- 用户正在进行线下互动时，与用户处于同一场景的角色暂停在聊天窗口回复，其回应发生在线下互动界面。
- 线下故事进行期间不能快穿，必须先结束当前故事。
- 其他世界的角色保持冻结，不会在此期间从聊天窗口发来消息。
- 结束共同场景中的线下互动后，角色是否回复聊天消息继续由其日程和状态决定。

### 2.8 线上与线下记忆互通

- 同一角色的线上聊天与线下互动共用持续记忆。
- 聊天中的约定、交流和关系变化会影响线下故事。
- 线下发生的事件、对话和关系变化也会影响后续聊天。
- 切换界面或地点不能使角色忘记已发生的共同经历。
- 世界冻结和恢复不清除角色记忆、聊天记录、关系或故事进度。

### 2.9 主动聊天与通知

- 当前世界的角色可以在用户没有发送新消息时主动发起聊天；其他世界的角色不会主动联系用户。
- 主动联系结合角色性格、时间、日程、当前状态、已有记忆和双方约定等信息。
- 主动联系频率由角色卡中的角色性格决定，不采用所有角色统一的联系频率。
- 用户关闭 APP 后也能收到当前所在世界的角色消息通知，其他世界继续保持冻结。
- 本阶段不提供免打扰功能，角色聊天新消息按始终通知处理。
- 主动联系同样遵守角色状态：正在与用户进行同场景线下互动的角色，不同时从聊天窗口发来消息。
- 主动消息沿用线上活人感与纯消息要求，通知预览中也不出现动作或旁白。

## 3. 典型使用流程

1. 用户导入角色 PNG，格式校验通过后将角色添加到通讯录；世界书缺失或没有名称时不能导入。按世界书名称加入对应世界，不存在对应世界时创建新世界；加入已有世界时合并条目，同名条目保留旧条目。
2. 用户进入该世界，与角色进行日常聊天，双方的交流形成持续记忆；其他世界的时间和角色活动保持冻结。
3. 当前世界的角色按照自己的日程活动，也会根据性格与双方经历主动联系用户；聊天新消息始终通知，用户关闭 APP 后仍可收到当前世界的消息通知。
4. 对话出现线下互动意图时，界面提供赴约或前往地点的按钮。
5. 用户点击按钮；如需跨地点移动，选择出行方式后进入“路上”状态，按世界书提供的移动信息消耗相应游戏内时间，到达目标地点。途中可以继续聊天，也可以选择加速推进的游戏内时长；当前世界的角色日程与活动随时间推进。
6. 在角色日程和位置允许见面的情况下，进入线下互动界面，与同一世界的一个或多个角色展开故事，通过选项或自由输入参与互动。
7. 与用户处于同一线下场景的角色暂停聊天窗口回复；故事进行期间不能切换世界，其他世界的角色也不会发来消息。
8. 线下互动结束后，故事经历保留在角色记忆中，影响后续聊天；后续回复时间继续受角色日程与状态影响。
9. 用户可以在故事结束后直接快穿到其他世界；原世界冻结，目标世界恢复运行。
10. 用户再次返回原世界时，从离开时的时间和状态继续，保留已有记忆与故事进度。
