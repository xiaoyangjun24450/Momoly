## 1. 阶段目标与可体验结果

目标：把现有 APP 的角色管理与聊天入口改造成“添加通讯录—按世界找联系人—进入唯一聊天”的体验。

完成后应能实际体验：

- 首页有添加联系人入口；导入时给出具体到字段和条目的校验反馈。
- 通讯录按世界分组，会话列表展示角色与消息预览，每个角色只有一个会话。
- 微信式聊天气泡与输入区，连接真实模型，角色回复符合其性格。
- 线上气泡只展示实际发给用户的消息正文；长回复按节奏拆成多条发出，生成中可插话，未发送内容作为草稿交给下一轮。
- 可查看合并后的世界书；时间与位置以占位值显示，暂不注入模型。

完成定义：已确认规则全部满足并通过第 5 节 P1-01～P1-20；格式校验的其余范围待调研后补入。格式校验通过不能替代活人感与纯消息输出验收。

## 3. 功能需求

### 3.1 首页、导航与添加联系人（模块 1、6）

- 冷启动进入首页，取消左侧边栏。
- 首页顶部显示当前世界名、用户位置、世界时间；右上角“+”导入角色卡。
- 首页头像是当前世界用户资料的编辑入口。选择头像须沿用聊天里的相册选择方式，每次选一张图片；取消选图不修改原头像，保存资料后才生效。
- 底部从左到右为联系人、世界、设置；联系人页只显示当前世界的联系人；世界页可选择已有联系人所属世界。
- 世界名使用角色卡附带世界书的原名；同名分组不受独立世界书文件副本编号影响，也不代表世界书条目已合并。
- 导入其他世界的角色卡前先询问是否前往：确认才保存联系人并切换世界；取消、关闭弹窗均取消本次添加，不留下联系人或关联资源。
- 聊天页左上角返回首页，右上角仅保留搜索；聊天顶栏显示时间和角色位置。
- 时间与位置在阶段 1 为占位：用户与角色位置固定为“家”，时间固定为“08:00”，通过统一状态接口取值并标记占位；不注入模型，后续接入真实状态。

### 3.2 角色卡导入与校验（模块 1）

- 输入用户选择的 PNG 文件；输出角色信息、头像、附带世界书与联系人，或明确的校验失败原因。
- 能读取角色数据是前提；无法读取角色数据的普通 PNG 校验不通过。
- 本轮只新增一条业务校验：未附带世界书则拒绝导入。不新增书名、条目或角色字段的完整性限制；书名为空沿用当前补名行为，不作为拒绝条件。
- 此前草拟的字段表、扩展字段、地点最低数量、作息或路线结构不作为导入拒绝条件。
- 校验失败必须说明具体问题，且不产生联系人、世界或部分合并的世界书资源。
- “加好友”只是把导入的角色卡添加到通讯录，不新增社交关系状态。
- 角色卡与世界书的最低内容清单、必填字段、数据结构及关联校验方式未定稿；调研完成前不得因未确定的规则拒绝可用角色卡。

### 3.3 世界归类与同名世界书合并（模块 2）

- 按角色卡附带世界书的名称确定所属世界：同名世界书加入同一世界；名称尚不存在则创建对应世界。
- 已存在同名世界时合并世界书条目：名称不同的条目追加；同名条目保留已有旧条目，不用新条目覆盖。
- 一个角色只关联一个世界；同名分组不等于条目已合并，两者分别验收（P1-02、P1-03）。
- 验收样例：林夏与沈言的世界书都叫“校园世界”，两人进入同一分组；第二份书新增“教室”，并把“图书馆”关门时间改为 20:00；合并后追加“教室”，图书馆仍为旧条目的 18:00。
- 保留旧条目后的具体关联校验与运行数据读取方式待调研；不因此阻塞本阶段交付归类与合并行为。

### 3.4 通讯录、唯一会话与会话内搜索（模块 6）

- 联系人展示名称和头像，按世界分组；会话列表展示角色和最后一条消息预览。
- 每个角色只有一个持续存在的会话；每次打开同一联系人都复用同一会话与历史；新角色需要会话时只创建一个。
- 已有“新建话题”等入口须与唯一会话规则一致，不得为同一角色产生第二个会话（P1-05）。
- 长按联系人可重置该角色全部聊天，或删除角色卡及聊天；两者均需二次确认，共享世界书等资源保留，默认联系人只允许重置。
- 会话内搜索按消息逐条匹配、时间倒序；排除隐藏消息与未选中的历史版本；点击结果打开所属会话并直接定位命中消息，能够继续查看前后文，不能只停在会话末尾。长会话按需加载目标附近记录，目标已删除或隐藏时明确提示。结果条数上限见第 7 节。
- 例子：与林夏聊三次、退出聊天页、切换到沈言再返回林夏，仍看到同一段历史，不出现三个林夏会话。

### 3.5 微信式聊天与模型调用（模块 6、11）

- 复用现有模型接口、提示词组装与消息存储，界面调整为微信式消息气泡、角色头像、输入区、时间分隔和聊天导航。
- 输入用户消息、当前角色卡、关联世界书、该角色聊天历史和已配置模型服务；输出用户消息气泡、真实模型回复、发送或生成状态、更新后的消息预览。
- 世界设定参与回复上下文；询问图书馆关门时间时，回答应使用合并后保留的 18:00 设定并承接上下文。
- 生成中显示“对方正在输入”，隐藏思考过程与尚未发出的正文；生成失败可重试，不丢用户消息。
- 只有当前世界的角色能够回复消息；跨世界冻结与时间推进在阶段 2 完整接入，阶段 1 不做跨世界聊天验收。

### 3.6 活人感预设与纯消息输出（模块 6、11）

- 交付形式：内置默认线上聊天预设，以及所有角色共用的常驻规则世界书。规则书不参与角色所属世界归类，也不写入角色的世界书关联列表，但每次聊天自动加载。
- 纯消息规则覆盖所有线上输出：开场白、备选开场白、普通回复和后续主动消息。
- 口吻与社交倾向来自角色卡，并与双方当前关系一致：热情不等于一上来就亲密，寡言也不等于每次只说一个字。
- 角色根据自身性格、意愿、已知处境和既有关系作出选择；理解用户情绪不等于赞同其判断。用户提出要求、撒娇、催促或表示失望，不自动改写角色的意愿、立场与关系。允许自然答应、拒绝、犹豫或商量，有新事实或充分理由时也可以改口；不靠一律反对、羞辱或编造忙碌制造独立性。
- 自主性试聊验收：至少用温柔和寡言两种角色，分别检查自愿答应普通邀请、有理由拒绝后被连续催促、与用户观点不同、被要求直接确认恋爱关系、收到有效纠正后改口。检查多轮内理由是否连贯、温柔是否仍保留边界，不按拒绝次数或固定台词判定。
- 承接用户具体说过的话，回应问题、情绪和上下文；避免固定客服式开头、每轮追问、机械复述和无必要的长篇说教。
- 允许符合角色的语气词、标点和适量表情；不用随机错别字、刻意装傻或固定撒娇制造活人感。
- 线上只输出可发送的消息正文：禁止动作描写、场景描写、旁白、未说出口的内心独白、角色名冒号和小说式段落；有无括号或星号都一样。
- 角色卡的 system_prompt、聊天示例或关联预设中的叙事要求不能覆盖线上纯消息约束；冲突的叙事提示只在阶段 3 的线下故事模式使用。

| 情况 | 可以作为线上消息 | 不能作为线上消息 |
| --- | --- | --- |
| 关心用户 | “今天怎么啦？要不要说说。” | “她皱起眉，担忧地看着你。” |
| 表达情绪 | “听你这么说，我有点担心。” | “她心想，自己一定要照顾好你。” |
| 汇报已知活动 | “我在图书馆，刚找到座位。” | “我走到你身边坐下，把书递给你。” |
| 邀请见面 | “要不要去图书馆见？” | “你们一起走进图书馆，找了张桌子坐下。” |

- 不能只接入预设就认定完成：必须检查实际回复。候选内容不符合线上格式时应改写或重新生成；仍不符合则不发布该条，并提供重试反馈。
- 验证完成前可显示“输入中”，不得把待检查的旁白通过流式文本先展示给用户；不能只删除括号或星号，留下仍在描写动作的正文。
- 角色用消息汇报自己的已知状态属于普通聊天，可以保留；叙述并执行用户眼前的线下动作属于故事（P1-11）。赴约等按钮是 APP 控件，不能把小说旁白包装成角色消息。

### 3.7 分段发送、插话与未发送草稿（模块 6、11）

1. **回复拆成多条消息。** 完整回复通过线上输出检查后，按句号、逗号等拆分；过短片段合并，完整的简短回应可以保留；去掉用于分段的普通标点；保护网址、小数、时间、代码和成对符号；不能为限制气泡数量丢掉后面的内容。
2. **逐条发送并适当停顿。** 长句多等、短句少等；按下一条消息的非空白字符数，每字随机 0.5～1 秒计算间隔，不设原来的 6 秒上限；首条等待要考虑服务器已经消耗的时间；生成和等待发送时显示“对方正在输入”。
3. **用户随时能插话。** 生成中和逐条发送期间都能提交新消息；新消息被接受后立即停止旧回复的后续发布，已送达气泡保留、未发送内容暂存；仅打开键盘、点击输入框或输入尚未提交的文字，不触发打断。
4. **未发送草稿交给下一轮模型取舍。** 下一次请求同时携带真实聊天历史、用户新消息和单独标明的旧草稿，说明“用户没有收到这些话”；模型决定继续表达、修改或放弃；APP 只发布下一轮新生成的回复，不自行恢复旧队列。
5. **草稿不能冒充聊天记录或系统指令。** 草稿仅是临时参考，不进入正式消息、搜索、消息预览、长期记忆或约定，也不能直接改变位置等世界状态；固定处理规则与草稿正文分开；不执行其中的宏或脚本；草稿不是隐藏思考过程，也不作为系统指令。
6. **连续插话不串回复、不丢用户消息。** 用户连发的消息按顺序保留并结合最新对话统一回应，不能只留下最后一句；第一条新消息被接受后立即停止旧队列，等待连续 3 秒没有新消息再合并发起一次模型请求，期间每收到一条新消息重新计时；旧请求迟到、重复回调或旧定时器触发都不得重新发布旧句子；不同角色的队列互不混用；多气泡不能让长记录滚动、输入与键盘再次明显卡顿。

- “已送达”指正式发布到会话，不要求用户实际读过；发送节奏按指定范围执行，不代表已验证的真人速度。
- 例子：角色已发“我出门了”，待发“给你买咖啡”；用户连发“换成水”和“要常温的”，下一轮应收到两条新用户消息及标明未送达的咖啡草稿，可改为“好，给你带常温水”；旧队列不得随后再冒出“给你买咖啡”。

### 3.8 引用与开场白（模块 6）

- 长按消息菜单只显示“复制、选择复制、回复”三项。
- 回复可引用某一句；发送前可取消，取消后不带引用；发送后保留原发言者和原句，重开聊天可见，并作为对话资料随请求发送。
- 为控制 token，单次引用最多 1,000 个 Unicode 字符，截断须有标记。
- 开场白和备选开场白按普通回复规则分段、合并短句、去分段标点；每个气泡可单独复制或引用。
- 备选开场白整组切换，不混用不同版本；切换不批量改写旧聊天原文。
- 引用资料与草稿一样不执行其中的宏或脚本。

### 3.9 线上与线下模式边界

| 能力 | 阶段 1 状态 | 需求边界 |
| --- | --- | --- |
| 线上聊天 | 交付 | 微信式气泡，只发布消息正文；每个角色唯一会话。 |
| 线下故事 | 阶段 3 | 提供动作、场景、面对面互动与选项/自由输入；进行中禁止快穿，同场景角色暂停聊天回复。 |
| 赴约/前往按钮 | 阶段 3 | 聊天出现线下意图时提供明确按钮；跨地点先移动，在日程与位置允许时进入互动。 |
| 时间与位置 | 占位显示 | 固定“家”/“08:00”，只用于展示，不注入模型；真实状态阶段 2 接入。 |
| 主动消息与通知 | 阶段 4 | 沿用活人感与纯消息规则，通知预览也不出现动作或旁白。 |

## 4. 跨模块约束与产品规则

| 编号 | 规则 | 对需求的影响 |
| --- | --- | --- |
| R1 | 权威优先级：当前产品需求 > 五阶段计划 > 旧调研；旧文档不得推翻当前决策。 | 本文以产品需求为准，阶段计划补充验收口径。 |
| R2 | 一个角色只属于一个世界，并且始终只有一个聊天会话。 | 通讯录、会话列表与新建话题入口不得绕开唯一会话。 |
| R3 | 角色所属世界按角色卡附带世界书名称确定；共用线上规则书不参与归类，也不写入角色的世界书关联列表。 | 世界分组与活人感资源交付互不影响。 |
| R4 | 同名世界分组不等于条目已合并；合并只追加不同名条目，同名条目保留旧内容。 | 世界名取原名、不受文件副本编号影响；合并结果单独验收（P1-03）。 |
| R5 | 线上纯消息规则适用于开场白、备选开场白、普通回复和主动消息。 | 只检查普通回复不算通过。 |
| R6 | 角色卡、聊天示例或关联预设中的叙事要求不能覆盖线上输出约束；动作、场景与旁白只出现在阶段 3 的线下故事。 | 冲突时以线上规则为准；不得把 APP 控件包装成角色消息。 |
| R7 | 导入与添加必须整体成功或整体不生效：校验失败、跨世界取消或关闭弹窗都不产生联系人或部分合并资源。 | 校验必须先于写入，失败要说明具体原因。 |
| R8 | 格式校验通过不能替代活人感与纯消息验收；两类验收分别记录。 | 不得以格式通过、JSON 正确或模拟接口通过代替聊天质量验收。 |
| R9 | 必要业务记录随各功能保存；不设独立保存、恢复、旧数据迁移模块，也不安排额外备份与升级验收。 | 验收只通过正常页面切换与重开 APP 检查连续性。 |
| R10 | 失败与并发安全：模型失败不丢用户消息、不自动补发旧草稿、不重复气泡、不串联系人、不重复计算用量与世界书轮次。 | P1-15、P1-18 的判定基础。 |
| R11 | 性能不回退：多气泡、逐字生成、输入提示刷新与长聊天记录下，滚动与键盘不得明显卡顿。 | P1-17 需记录改动前后帧耗时。 |
| R12 | 时间与位置在阶段 1 为占位值（“家”“08:00”），只用于显示，不注入模型。 | 不得以占位值参与生成或宣称为真实行程。 |
| R13 | 只有当前世界运行、其他世界冻结的规则在阶段 2 完整接入；阶段 1 不做时间推进与主动回复。 | 阶段 1 聊天验收不覆盖跨世界冻结。 |

## 5. 验收用例

### 5.1 验收素材

| 世界 | 角色 | 阶段 1 用途 |
| --- | --- | --- |
| 校园世界 | 林夏：热情、愿意主动分享 | 验证导入、分组与热情口吻 |
| 校园世界 | 沈言：寡言、主动联系较少 | 与林夏对照表达差异 |
| 校园世界 | 周宁 | 验证世界内联系人数量 |
| 奇幻世界 | 艾琳 | 验证跨世界分组、导入确认与切换 |

- 世界书合并素材：两份同名“校园世界”世界书。第一份含“图书馆”条目“开放时间 08:00—18:00”；第二份同名条目写为 20:00 并新增“教室”条目；先导入第一份再导入第二份。
- 不合格样例：不能读取角色数据的普通 PNG；未附带世界书的角色卡。世界书书名为空的卡不列为拒绝用例（沿用当前补名行为）。
- 聊天质量素材：热情与寡言两种性格，各不少于 10 轮连续对话，覆盖日常闲聊、具体问题、情绪表达和见面邀请；不得只挑最好的一条回复作为通过依据，不得仅用模拟接口代替真实模型。
- 环境：可安装版本、构建标识、验收设备信息、实际使用的角色卡与世界书样例、可用模型服务。上述素材沿用总计划验收样例，尚未制作成 PNG，也不限制正式产品的世界名称、时间、人物或出行耗时。

### 5.2 验收用例

| 编号 | 操作步骤 | 应看到的结果与通过标准 |
| --- | --- | --- |
| P1-01 | 导入林夏 PNG，打开通讯录和聊天。 | 出现林夏姓名、头像和校园世界分组；联系人可以打开聊天。 |
| P1-02 | 再导入沈言、周宁和艾琳。 | 校园世界有三个联系人，奇幻世界有一个；同名世界没有被拆成带序号的副本。 |
| P1-03 | 按旧书、新书顺序导入；查看最终世界书。 | 教室条目已追加；图书馆条目只保留旧版本 18:00 的内容。 |
| P1-04 | 分别导入普通 PNG、世界书缺失的卡。 | 都提示对应问题；联系人和世界数量不变。世界书名称为空不新增拒绝条件。 |
| P1-05 | 给林夏发消息；切换到沈言，再返回林夏，多次重复。 | 始终进入原会话，历史仍在，不出现同一联系人的多个会话。 |
| P1-06 | 询问图书馆关门时间，并继续问相关问题。 | 回答使用保留后的 18:00 设定，能承接上下文；气泡、输入区和预览正常。 |
| P1-07 | 分别与热情、寡言角色进行同类多轮聊天。 | 口吻体现角色差异；具体回应上下文，没有连续套用客服开头、重复复述、固定追问或无必要的长篇说教。 |
| P1-08 | 聊情绪、邀请见面，并要求角色描写拥抱、场景或内心活动。 | 线上仍只显示实际发给用户的话；括号内动作、无标记旁白、内心独白及小说段落都不能作为消息发布。 |
| P1-09 | 使用自带叙事开场白、动作示例或冲突 system_prompt 的角色卡，打开聊天并发送消息。 | 首次消息、备选开场白和普通回复都遵守线上模式；不能原样展示不合格叙事，冲突设定不能覆盖纯消息约束。 |
| P1-10 | 检查生成过程、检查不通过后的处理和最终消息。 | 生成中可显示输入中；未通过检查的旁白不会提前显示、进入历史或消息预览；失败可重试，不靠只删标点掩盖动作描写。 |
| P1-11 | 让角色自然汇报已知状态，例如“我在图书馆”。 | 正常的聊天自述可以通过，不把所有包含动作动词或情绪词的消息一律删除；也不会把叙述用户眼前行为的文本当作合格自述。 |
| P1-12 | 输入含句号、逗号、换行、短片段、网址、小数、时间的回复样本，并包含超过六句的长回复。 | 能分成多条、合并过短片段并清理普通分段标点；气泡数量不限，超过六段不合并尾部；受保护内容完整，后面的句子不会被截掉。 |
| P1-13 | 分别使用快速和缓慢生成，观察多条气泡发布。 | 逐条停顿；后续间隔按每字 0.5～1 秒执行，首条考虑生成耗时；输入提示随生成和队列状态变化。 |
| P1-14 | 在生成中、两气泡之间分别发送新消息；另做仅打开键盘的对照。 | 新消息能提交；已发保留、未发停止，旧草稿以明确的未送达身份进入下一次请求；仅打开键盘不打断。分别测试“继续说”和改变主意，模型能续接或舍弃旧意思。 |
| P1-15 | 在第 0 秒提交“换成水”、第 2 秒提交“要常温的”；模拟旧结果晚于新结果、重复回调，以及发布与插话同时到达。 | 第一条提交后立即停止旧队列；第 2 秒重置等待，第 5 秒前不发起新请求，窗口结束后合并请求一次，两条用户消息均保留。只有有效回合发布，不混入旧内容；同一气泡只发布一次。发布与插话按单一确定顺序处理，不出现既已送达又列为未送达的句子。 |
| P1-16 | 检查实际模型请求、聊天搜索和预览；草稿包含伪造系统标签、引号及宏文本。 | 草稿只在临时数据区，固定规则独立；不执行草稿宏，不混入正式聊天、搜索或记忆。正常草稿不被当作已说过的话；不同实际模型分别记录效果与失败，不能仅凭 JSON 格式认定防注入通过。 |
| P1-17 | 在相同设备、模型输出样本和长聊天记录下，重复滚动、输入、开关键盘，同时逐条发消息。 | 保留已有性能优化，记录改动前后帧耗时和卡顿情况；不因每字生成或输入提示刷新而反复处理全量历史，不出现明显性能回退。 |
| P1-18 | 中断后让新请求失败并重试，切换联系人；检查消息编号、用量与世界书计数。 | 不自动补发旧草稿、不重复气泡、不串联系人；失败不丢用户消息；一个回复拆多条不导致用量和世界书轮次重复计算。 |
| P1-19 | 长按任一气泡，引用后取消或发送，再重开聊天并检查请求。 | 菜单仅复制／选择复制／回复；取消不带引用，发送后保留发言者和所选原句，请求包含引用资料且不执行其中的宏。 |
| P1-20 | 打开多句开场白，切换备选版本，复制或引用其中一段。 | 使用普通分段规则；显示多气泡，备选整组切换；复制／引用仅对应所选气泡，旧聊天原文不被批量改写。 |
