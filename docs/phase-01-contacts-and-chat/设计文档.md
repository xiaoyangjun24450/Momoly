## 1 设计目标与约束

目标：导入角色卡即"加好友"，按世界书名称分组联系人，一个角色只有一个持续会话；聊天达到微信式体验，线上只呈现消息正文；完整回复分段逐条发送，用户可随时插话，未发正文作为草稿进入下一轮，引用与开场白遵守同一分段规则。

| 约束 | 落地方式 |
| --- | --- |
| 单 Activity、无导航库 | `ChatDestination` 返回栈 + `ChatDestinationHost` 渲染栈顶；消息滚动由 `ChatScrollController` 单一持有 |
| 依赖方向 | `app → feature → domain/core`，数据实现在 `data:*`；`di/AppContainer` 手工装配，根任务 `checkArchitecture` 是发布门槛 |
| 不额外调用判断模型 | 分段、3 秒合并、打断判定全在本地 Kotlin 完成，不引入外部机器人/语音运行时 |
| 线上纯消息 | 由默认预设与全角色共用规则书约束（见 §4.7）；APP 暂未实现独立发布前语义检查 |
| 阶段边界 | 时间与位置用固定占位（`isPlaceholder`），不注入模型；世界书条目合并、完整格式校验不在已实现范围 |

工程事实（模块职责、UI 组件、Room/Paging 约定）见 [CLAUDE.md](../../CLAUDE.md)。

## 3 数据模型与存储

| 数据 | 存储 | 关键约定 |
| --- | --- | --- |
| 会话 | Room `sessions` | `id`、`charFile`、`charName`、`createdAt/updatedAt`、`localVariablesJson`、`timedWiJson`（世界书定时效果状态）、`extStateJson`（扩展会话状态）、`title`、`pinned`；一个联系人复用同一会话 |
| 消息 | Room `messages`，主键 `(sessionId, ts)` | `ts` 会话内严格递增（LazyColumn key）；`role/content`、`altsJson`+`altIdx`（同位置多版本，`content` 等镜像当前版本）、`dataJson`、`isHidden`、`replyToJson`、`imagesJson/filesJson/searchJson`、token/耗时、`requestSnapshotsJson` |
| `dataJson` | `messages.dataJson` | 前端/MVU 私有状态 JSON 对象；空串表示无、读出补 `{}`；不属于本阶段业务语义，也不进提示词 |
| 引用字段 | `messages.replyToJson` | `MessageQuote(messageTs, role, author, content, truncated)` 快照；可空语义，v15 Migration 14→15 `ADD COLUMN ... DEFAULT ''`，旧记录升级后无引用 |
| 草稿 | 不落库 | `ChatReplyScheduler` 内存 `Map<sessionId, InterruptedReplyDraft(turnId, text)>`；每会话仅一份有效草稿，新草稿替换旧草稿；进程结束即丢 |
| 世界用户资料 | `SharedPreferences("world_user_profiles")` | 键 `world:<世界名>`，值为 `{version:1,name,description,avatar,configured}`；头像在 `filesDir/world_user_avatars/<uuid>.jpg`；空世界名为"未分配世界"；`migrated` 标记一次性从旧全局资料复制；坏数据 `readFailed` 且不覆盖，明确保存才替换 |
| 默认资源 | `assets/defaults/` 随包内置 | 预设 `purpose=online_chat, version=5`；共用规则书 `id=momoly-online-chat-rules-v1, purpose=online_chat_rules, version=4`；按 `extensions.momoly.version` 判旧版本替换，保留已装文件名、ID 与角色关联，自定义资源不受影响 |
| 角色/世界书/预设 | `filesDir` 下每实体一个 JSON 文件（`JsonFileDir` 原子写） | 角色卡 `world_name` 存世界书原名（旧卡回退 `character_book.name`）；内置规则书不写入角色世界归属与导出载荷 |

聊天记录是存储例外：Paging 3 分页 + 实时 overlay 合并，流式生成不逐帧写库；v9 为公开发布迁移基线，之后每次结构变更必须注册显式 `Migration`、提交 `schemas` 快照并补旧库升级测试，禁止 destructive migration。

## 4 接口与关键流程

### 4.1 回复分段与逐条发送（已实现）

- 分段：`ChatReplyText.split` 按 `，,。.!！?？;；…` 与换行拆分；URL、邮箱、Markdown 链接、数字/时间、行内代码与代码块、成对引号/括号内的内容受保护；不足 3 个 code point 的片段合并，末尾短片段并入前段；整条只有标点时保留原文；不限制气泡数量。
- 节奏：`gapMillis = 下一段非空白 code point 数 × 随机 500～1000ms`，emoji 按 1 个 code point；无原 6 秒上限；首条扣除从接受到已生成的时间，不重复等待。
- 发布：`ChatReplyScheduler` 在 `gate` 内逐条 `publish`；首条由 `ChatGenerationRunner.publish` 在 `commitReply` 事务中同时提交消息、局部变量与世界书定时状态，用量只记首条；后续 `putMessage`；生成后处理整轮只运行一次。
- 失败：已送达气泡保留，未发正文转草稿；不撤回用户消息、不发布错误气泡、不自动恢复旧队列。重答某条角色消息是单条版本替换（`splitReply=false`），从用户消息重答走分段发送。

### 4.2 插话接管与 3 秒合并（已实现）

- 每次 `submit` 递增 `revision`、取消上一轮任务，并在 `gate` 内先提交用户输入；输入保存不被后续输入取消，已经开始的提交先完成，网络与等待不占锁。
- 旧轮未发内容按 `segments.drop(sent)` 以换行拼接（生成中则取部分正文）写入草稿，最多 16,000 字符；立即停旧队列。
- 从第一条新消息被接受起等待至连续 3 秒无新消息才发起请求，每条新输入重置计时；仅打开键盘、点击输入框或输入未提交不触发打断。
- 旧结果、旧定时器与重复回调靠每步 `revision` 比对丢弃，不发布旧句子；切换联系人停止原队列，草稿按会话隔离，删除联系人时同步清理队列与草稿。

### 4.3 草稿回灌（已实现，语义效果未验收）

- 只包装请求副本中的最新 user 消息，不改库内原文与附件：`app_context = {type:"interrupted_reply_draft", source_turn_id, undelivered_text, truncated, latest_user_message}`；`latest_user_message` 同时保留用户新输入。
- 限额：内存草稿 16,000 字符；请求取前 4,000 字符；token 上限 = `min(1024, 剩余预算/4)`，剩余预算扣除固定提示、深度注入、规则提示与最新连发输入后再留 128；从尾部逐字裁剪并标记 `truncated`。
- 包装发生在历史正则/宏处理之后，草稿正文不执行宏与脚本；有草稿时附加固定 `DRAFT_RULE`，普通轮次不加；草稿不进入正式消息、搜索、预览、记忆或世界状态。

### 4.4 引用（已实现）

- 长按气泡菜单仅"复制/选择复制/回复"；选中气泡生成 `MessageQuote` 快照（不引用整组开场白），发送前可取消；发送后随用户消息 `replyToJson` 持久化，重开聊天可见。
- 请求同样在正则/宏之后包装最新 user 消息：`app_context.quoted_message = {message_ts, role, author, text, truncated}`，`text` 最多 1,000 个 Unicode 字符；无引用不附加 `QUOTE_RULE`；有未发草稿时与草稿共享同一个 `app_context`。
- 引用随消息参与历史预算裁剪；最新连发用户消息强制保留；引用正文不运行宏/脚本，JSON 包装不构成提示注入防护。

### 4.5 开场白与备选开场白（已实现）

- 新会话把 `first_mes` 作为首条 assistant 消息，`alternate_greetings` 作为同位置 `alts` 整组版本（`model` 为空）。
- 界面与请求都由 `PromptMessageAssembler` 识别首条开场白并按普通分段规则展开为多气泡，第一段携带图片；存储仍保留原文与整组版本。
- 一次展示全部分段、不进入延时发送队列；切换备选整组替换，不批量改写旧聊天；每个气泡可独立复制/引用。

### 4.6 世界归类与世界书合并（归类已实现，合并未开始）

- 分组身份是角色卡 `world_name`（导入时写入世界书原名；书名为空沿用"角色名 世界书"），首页与联系人页按该值分组，空值为"未归属世界"；全局聊天规则书不参与归类，同名分组不等于条目已合并。
- 跨世界导入先询问：确认才写角色与关联资源并切世界，取消或关闭不留下角色、头像或世界书。
- 当前每个导入的世界书仍是独立文件副本（重名自动加后缀），因此不能引用"合并后保留旧条目"。
- 计划规则（未实现）：按书内 `name` 精确归类；追加不同名条目；同名条目完整保留旧对象（含启用状态、关键词、位置、优先级、扩展与未知字段）；同一世界只保留一份有效书；名称与条目 ID 分开（不同书整数 ID 不能作身份）；先算校验与合并结果，成功后整体提交，失败不留半次合并。

### 4.7 活人感与纯消息约束（资源已落地，效果未验收）

- 默认预设负责线上编排与输出边界：main/jailbreak `forbid_overrides` 挡角色卡覆盖，约束只输出可发送正文；共用规则书补中文表达习惯、短反应与情境示例，由 `PromptContextLoader` 在每次加载时置于书单首位，所有角色自动共用。
- 2026-11-06 自主性调整：预设 v5 明确梦鲸的创作体验不等于满足用户每个要求，本轮回复依据角色意愿作决定；规则书 v4 补充情绪与判断分开、连续催促下的边界、有效理由下的改口，以及答应／拒绝／不同意见的对照语境。保留道德经与阴符经原文、接梗、短反应与自然语气，不新增固定拒绝比例或统一强硬口吻。沿用默认资源版本更新机制，独立自定义预设不强制切换。
- APP 侧没有独立语义检查与"不合格不发布 + 重试"链路；叙事开场白、冲突预设的过滤目前只靠提示词约束，不能宣称零旁白，效果必须用真实模型试聊验证。

## 8 风险、限制与技术债

- 队列与草稿只存于 ViewModel 内存，杀进程/冷启动不恢复；已送达消息与用户输入正常落库，不自动补发旧内容——后台持续发送/进程恢复需另做持久化（与阶段 4 相关）。
- 世界书条目合并未完成：同名世界只在 UI 分组，条目仍是两份独立副本，旧条目保留规则（P1-03）当前无法通过。
- 导入仅"缺书拒绝"一条业务校验；空书、无名条目、重复 ID、未知字段、类型错误的行为未定。
- 纯消息无发布前语义检查，提示词约束无法保证零旁白与低误杀；不合格内容仍可能发布，必须真实模型验证。
- 草稿/引用的 JSON 包装不保证模型不受误导（误认已送达、泄露内部说明、伪造指令），也不是提示注入防护；真实模型效果未测。
- 世界资料仅本机；手动备份的"头像"分区仍处理旧全局头像，尚未扩展世界资料跨设备导入导出；未做世界重命名迁移与多设备测试。
- 跨存储操作（全局变量、角色/世界书文件与聊天数据库）不保证故障时整体回滚。
- 验证覆盖有限：单设备/单样本性能、部分供应商与多模态、复杂脚本卡、其他设备未逐一实测，不能外推。
- 阶段 1 未标记人工验收通过，验收用例见 [需求文档](需求文档.md)，不再重复。
