# Momoly 角色陪伴 APP 文档总览

> 文档边界：每个阶段最多 3 篇——[需求文档](phase-01-contacts-and-chat/需求文档.md)（产品经理）、设计文档（研发）、调研文档（参考资料）。规则见 [AGENTS.md](../AGENTS.md)。本页只放跨阶段的定位、路线、统一验收素材、决策记录与索引。

## 1. 产品定位

把 Momoly 做成以角色扮演和情感陪伴为核心的 APP：类似微信的即时聊天，加上文字游戏／交互小说式的线下互动。

- 导入 SillyTavern 兼容角色卡即"加好友"；每个角色只有一个持续存在的会话和一份持续记忆。
- 角色按世界书归入世界；同一时间只有用户所在的世界运行，其他世界的时间与角色活动全部冻结。用户以"快穿"切换世界。
- 同一世界内移动消耗游戏内时间，用户可加速推进；角色按日程移动、活动、回复。
- 角色会按性格、日程、记忆与约定主动联系；关闭 APP 后仍能收到当前世界的消息通知。
- 线上聊天只发消息正文（活人感、无动作/场景/旁白）；动作、场景与旁白只出现在线下故事。

## 3. 统一验收素材

以下为计划使用的验收样例，尚未制作成图片或导入 APP；不限制正式产品的世界名称、时间、人物或出行耗时。

### 3.1 世界与角色

| 世界 | 角色 | 验收用途 |
| --- | --- | --- |
| 校园世界 | 林夏：热情、愿意主动分享 | 验证角色日程、主动联系和共同故事 |
| 校园世界 | 沈言：寡言、主动联系较少 | 与林夏对照联系安排，验证多人故事 |
| 校园世界 | 周宁：本次故事不在场 | 验证未参与角色不会自动获得私人经历 |
| 奇幻世界 | 艾琳 | 验证跨世界切换、时间冻结和消息限制 |

校园世界初始验收时间为 08:00，奇幻世界为 10:00，两者各自保存游戏时间。

世界书合并样例：两份同名"校园世界"世界书，第一份含"图书馆"条目（开放时间 08:00—18:00）；第二份同名条目写 08:00—20:00 并新增"教室"。先导入第一份、再导入第二份，最终保留 18:00 的旧条目并追加"教室"。

阶段 1 样例保留普通 PNG、世界书缺失；阶段 2 追加缺图、无效地图、缺初始位置/时间/背景及无效地点等用例，以[阶段 2 需求](phase-02-world-time-and-travel/需求文档.md)为准。书名为空继续沿用补名行为，其他未确认限制不得自行加入。

### 3.2 地点与出行数据

| 路线 | 步行耗时 | 骑行耗时 |
| --- | --- | --- |
| 家 → 教室 | 20 游戏分钟 | 8 游戏分钟 |
| 教室 → 图书馆 | 10 游戏分钟 | 4 游戏分钟 |
| 家 → 图书馆 | 25 游戏分钟 | 10 游戏分钟 |

以上数据写入验收世界书；需要返程的用例应同时提供返程信息。阶段 2 仅用于角色移动验证，用户出行用例后移。

### 3.3 日程与共同经历

林夏的验收日程：08:00—08:30 在教室忙碌，08:30—08:40 步行前往图书馆，08:40—10:00 在图书馆空闲。沈言在 08:00—10:00 位于图书馆；周宁在家。

统一记忆事件：用户在线上约定 09:00 在图书馆见面并带一本红色封面的书；见面后把书借给林夏，沈言在场目睹，周宁未参与且未被告知。

## 4. 每阶段共同的验收方式

1. 交付可安装版本、构建标识、验收设备信息，以及实际使用的角色卡和世界书样例。
2. 按阶段需求文档的验收用例逐项操作并记录实际结果；文档中的预期结果不能直接当作已经通过。
3. 截图证明界面与状态；录屏证明时间推进、移动、切换和通知等连续行为；通过正常页面切换或重开 APP 检查业务状态连续性，不安排额外备份恢复验收。
4. 涉及生成内容的用例连接实际配置的模型服务；AI 措辞不要求逐字一致，但人物、事件、状态和知情范围必须符合用例。
5. 每阶段回归前面阶段的关键路径；角色消息、世界进度、故事和记忆的记录由各业务模块处理。
6. 验收技术记录独立于用户界面：用户看到的是联系人、时间、位置、故事和消息，不需要看到内部调度或提示词细节。
7. 线上只展示消息正文的规则适用于开场白、普通回复、重新生成和主动消息；格式校验通过不能替代活人感与纯消息输出验收。

| 日期 | 决策 | 归属 |

| 2026-11-04 | 当前世界按 3:1 自然推进，关闭后重开补齐；其他世界冻结；休息快钟后展示期间留言，聊天间隔至少 5 游戏分钟显示时间 | 阶段 2 |

| 2026-11-04 | 缺图且目标世界无图拒绝导入；角色必有初始位置/时间/背景，已有世界自动适配；资料与鉴定、可变世界书纳入 | 阶段 2 |
| 2026-11-04 | App 未上线，不做旧角色/旧格式兼容，不据此删除本机现有数据 | 阶段 2 |
| 2026-11-01 | "加好友"即导入角色卡并添加到通讯录；一个角色只属于一个世界、只有一个会话 | 阶段 1 |
| 2026-11-02 | 导入暂只新增"未附带世界书则拒绝"一条校验；书名、内容完整性与字段结构待调研 | 阶段 1 |
| 2026-11-02 | 线上只发布消息正文；动作、场景、旁白只属于线下故事 | 阶段 1（边界适用于阶段 3-4） |
| 2026-11-02 | 分段发送/插话/未发送草稿六条纳入阶段 1；引用与开场白按普通分段规则 | 阶段 1 |
| 2026-11-02 | 世界间可直接快穿；同一世界内移动消耗游戏内时间，可加速推进；基础耗时由世界书提供 | 阶段 2 |
| 2026-11-02 | 只有当前世界运行，其他世界时间与活动全部冻结；返回时从冻结点继续并保留记忆 | 阶段 2 |
| 2026-11-02 | 角色按日程移动与活动，日程影响能否见面、何时回复消息 | 阶段 2 |
| 2026-11-02 | 同一世界多个角色可参与同一段线下故事；故事期间禁止快穿；线上/线下记忆互通 | 阶段 3 |
| 2026-11-02 | 主动联系频率由角色卡性格决定；仅当前世界可联系；不支持免打扰，聊天新消息始终通知 | 阶段 4 |
| 2026-11-02 | 关闭 APP 后仍收到当前世界的消息通知，点击回到原会话 | 阶段 4 |
| 2026-11-02 | 后续地点及出行信息由 agent 生成并接入出行、故事 | 阶段 5 |
| 2026-11-01 | 取消独立的保存、恢复、旧数据迁移模块及备份恢复验收 | 全局 |
