## 1. 目标与阶段调整

让当前世界按自己的时间持续发展，让角色有日程、位置、心情和关系，能够主动聊天；用户可通过地图、角色资料与鉴定了解角色，通过休息快进看到期间的变化和留言。

| 本阶段交付 | 本阶段不做 |
| --- | --- |
| 3:1 世界时间、切换冻结、关闭后重开补齐 | 后台模型生成、系统通知、后台通知最小验证 |
| 休息快进、快走时钟、期间留言、聊天游戏时间标记 | 用户出行、赴约、见面、单人/多人线下故事 |
| 世界地图、用户/角色位置、地图导入检查 | 自动生成缺失地图、自动拓展新地点 |
| 时间段日程、角色活动与移动、忙闲回复、主动聊天 | 全员统一固定联系频率、用硬性低日限额替代角色行为 |
| 隐藏的心情与好感度、资料页与鉴定 | 旧角色/旧格式兼容、旧数据补全迁移、独立备份恢复建设 |
| 初始信息检查、已有世界入场适配、动态背景、可变世界书 | 擅自清空本机数据、修改固定世界设定 |

主动聊天从阶段 4 提前到阶段 2；阶段 4 保留后台执行、通知与线下经历联动增强。用户出行后移，后续阶段再细化实施与验收。原阶段 2 的用户出行用例及后台测试通知用例不再有效。阶段 1 的遗留验收仍保留，不据此宣称阶段 1 完成。

## 2. 世界时间、冻结与关闭后补齐

- 正常流速：现实 1 分钟对应游戏 3 分钟，包含日期与跨午夜推进。
- 各世界独立保存时间；任意时刻只有用户当前世界运行。其他世界的时间、日程、移动、心情演变及消息任务全部冻结。
- 世界间直接切换，不消耗出行时间。切换时先结算离开的当前世界，再冻结它并恢复目标世界；返回后从冻结点继续，不补算在其他世界期间的时间。
- 新建世界采用首个角色的初始时间；后续加入角色不能重置世界时间。
- 关闭 App 后，最后所在的世界仍按 3:1 经过。重开时补齐经过期间的活动、天气、位置、相关状态变化和角色留言；其他世界保持冻结。
- 关闭期间不要求进程常驻、不执行后台模型生成、不发系统通知。重开后的补算不能宣传成关闭期间实时执行。
- 时间、地图、鉴定和聊天共同使用真实世界状态，替换阶段 1 的占位时间/位置。实际状态进入相关生成上下文，占位值不得作为事实使用。
- 时间经过量只能结算一次；反复开页面、重试或重启不能把同一段时间重复推进。长时间离线的分批处理、系统时间异常和补算中断恢复策略见待定项。

## 3. 休息快进与消息时间

### 3.1 休息体验

- 用户选择休息的游戏内时长；其含义是用户在角色世界中睡觉/休息。
- 推进期间显示一个快速走动的时钟；处理完成后展示期间多条角色消息，消息保存在各角色原有会话中。
- 时间推进需经过中间事件，按事件发生时的状态处理日程边界、移动、天气、延期回复、主动联系与背景变化；不能只改结束时间。
- 角色可能留下很多消息；没有用户回应不等于整个世界停止活动。性格和事件决定是否再次联系，不固定为每次休息一条摘要，也不凭空补出用户回复。
- 历史留言不再按普通聊天逐字等待播放，之后实时新消息沿用阶段 1 发送节奏与插话规则。
- 各条留言使用其实际游戏发生时间和当时可知的信息，不能在早上的留言中引用下午才发生的结果。
- 精确入口、时长选项、多角色留言如何弹出、休息中途取消/失败后的界面属于设计待定；时钟不是完成证明，处理失败不能显示全部完成或静默丢掉待处理事件。

### 3.2 聊天时间标记

- 同一会话相邻两条已发布消息的游戏时间相差至少 5 分钟时，在后一条消息前显示游戏内时间。
- 用户消息、普通回复、主动留言和休息/离线补齐的消息遵守相同规则。
- 首条消息显示时间；跨游戏日期时显示日期和时间（显示细则沿用本轮整理，格式由界面设计确定）。
- 游戏发生时间与实际生成/保存时间分别记录；补齐的留言不能全部显示为重开 App 的时间。
- 消息稳定标识与存储顺序不能通过改写为游戏时间破坏；同刻多条消息保持确定顺序。此处只规定结果，字段与存储方式见设计文档。

## 4. 地图、位置与导入规则

### 4.1 地图界面

- 底部导航增加“地图”，展示当前世界的地点、用户与角色的当前位置。
- 每个世界共用一份有效地图；角色按日程活动与移动，地图显示对应位置或移动状态。
- 用户本阶段没有出行操作，地图不提供赴约、见面或线下故事入口。
- 用户/角色初始位置及日程中的地点必须能对应到地图，避免名称相似却指向错误地点。
- 角色跨地点活动需有合理移动时间；已声明的路线/耗时以世界书为依据，不用示意坐标距离冒充时间。
- 示意地图、人物头像、导航排序、区域层级与路线绘制是设计建议，不作为已确认视觉稿。

### 4.2 必备地图检查

| 角色卡/目标世界情况 | 结果 |
| --- | --- |
| 卡没有地图，目标世界也没有有效地图 | 拒绝导入 |
| 卡没有地图，目标世界已有有效地图 | 复用目标世界地图，其他检查通过后允许导入 |
| 创建新世界 | 首个角色卡必须携带有效地图 |
| 卡提供了地图但格式错误或必填内容缺失 | 明确指出错误；不将无效内容当作有效地图或悄悄忽略错误 |
| 卡与已有世界都提供有效地图 | 检查新增与冲突；合并细则待设计，不静默覆盖现有状态 |

缺图提示：“无法导入：角色卡未附带世界地图，目标世界也没有可用地图。请补充世界地图后重试。”

缺图不自动生成、不提供补全流程；失败/取消时不留下联系人、会话、本次新增附属资源或部分世界书改动。地图的识别标记、版本、地点/路线字段、冲突规则在设计中确定，不把建议格式冒充通用角色卡标准。

## 5. 初始信息、背景与导入预览

- 角色必须提供初始位置、初始时间和给用户阅读的简要背景；缺少必填信息时拒绝导入，说明原因，不静默编造。
- 初始位置必须是有效地图地点；时间与背景需可理解且相互一致。具体字段承载和合法时间表达待设计，不新增无关格式门槛。
- 新建世界：以首个角色的时间建立世界，使用其有效初始位置和开局背景。
- 加入已有世界：按目标世界当前时间、已有世界书和当前事实自动更新角色入场背景，保留核心身份和性格。卡的时间不同本身不再作为拒绝条件。
- 适配后的背景和位置必须一致；必要的位置调整只使用现有有效地点，不自动新增地点。不凭空制造该角色与用户或其他角色已经共同经历过的私人事件。
- 导入预览展示“此时此刻”和“前尘往事”；先完成适配再预览、确认后整体保存是推荐交互，具体确认流程待设计。
- 适配失败应明确提示并可重试，不保存半个角色或部分世界状态。
- 原卡中的设定、适配后的入场事实与后续变化需要可区分，不能因当前背景更新而抹掉原有身世。

## 6. 角色资料与鉴定

| 入口/页面 | 内容 |
| --- | --- |
| 导入预览 | 此时此刻、前尘往事 |
| 角色资料页 | 前尘往事，以及鉴定入口 |
| 鉴定页面 | 此时此刻、真实日程、心情、好感度 |

- “此时此刻”说明当前处境，包含当前位置和世界时间，随实际世界/剧情发展更新；导入后不作为普通资料页独立栏目。
- “前尘往事”承载角色身世与过往；是否自动追加后续经历及哪些信息向用户公开，属于建议未确认项。
- 鉴定从角色资料页进入，替代此前首页长按角色菜单中的鉴定入口。
- 鉴定读取真实系统状态，不能让模型临时编一份日程、心情或好感数值。更新中的状态不能互相矛盾。
- 查看鉴定不改变数值、不额外推进世界、不使角色自动获知被鉴定。完整日程和关系状态平时隐藏，用户主动鉴定时可见。
- 资料页的具体进入方式、鉴定显示日程的时间跨度及数值样式待设计。

## 7. 天气

- 增加天气系统，与世界时间、休息推进及关闭后补齐联动。
- 同地区同一时刻保持一致，相关角色生成使用同一份天气状态。
- 天气可影响话题、心情及允许调整的活动，但不能无条件取消所有固定日程。
- 推荐使用符合世界书气候设定的模拟天气；来源、变化粒度、地区差异、显示位置属于建议未确认项。世界特殊气候优先于通用模板。

## 8. 角色日程与忙闲回复

- 日程由开始—结束的时间段组成，不以孤立时间点代替活动区间。
- 每段描述活动、地点与交流状态：能否看消息、能否简短回复、能否正常聊天。
- 角色拥有自己的日程，可以随聊天中实际达成的约定添加、调整或取消；提议、传闻、未发送草稿不直接算已确认安排。
- 忙碌时可能简短/敷衍回应，也可能不回；空闲后应有机会处理未回复内容。敷衍不自动等于关系恶化。
- 用户连续留言保留，角色可结合上下文统一回应，不因暂缓丢消息或重复补答。
- 角色的地点、日程与实际活动一致，移动需占用时间；同角色不能同时执行冲突活动。
- 日程在普通界面隐藏，在鉴定中显示真实内容。冻结世界不执行日程或延期回复。
- 初始日程来源、重规划频率、冲突取舍、跨日计划与未回复消息过期规则仍需设计；推荐依据角色/世界设定生成，不要求作者提供整张作息表。

## 9. 主动聊天

- 当前世界角色在用户未发新消息时也能主动联系，且不依赖对应聊天页保持打开。
- 时间、日程、性格、天气、心情、好感与已知约定共同影响联系机会和内容；不同角色不同，不采用全员固定频率。
- 角色空闲后可先处理延期回复再分享话题，避免漏答与重复问候。
- 休息和关闭后补齐可产生多轮留言；其他世界不能产生消息。
- 复用原会话，不伪造用户消息，不把主动消息做成新的会话或纯系统摘要。
- 遵守阶段 1 的纯消息正文、分段、实际发送记录、插话与未发送草稿边界。
- 生成中切世界或状态变化时，提交仍需校验是否允许发布；旧结果不能污染新状态。
- 本阶段不做系统通知、后台生成或后台路径最小验证；应用内新消息提示应让用户发现新增留言，具体提示和未读样式待设计。

## 10. 好感度与心情

- 好感度是角色对用户较长期的关系态度；心情是较短期的情绪，两者独立但可共同影响表达和联系意愿。
- 初始关系和情绪参考角色设定，随后由真实互动、活动和事件变化；不能按消息条数机械加好感。
- 高好感不代表永远空闲，忙碌/疲惫不自动扣好感。用户休息本身不自动当作恶意冷落。
- 普通界面隐藏，鉴定可见；数值范围、初值、变化幅度、情绪维度和恢复规律未确认，不能硬编码为已拍板产品规则。
- 同一事件不能因重试、重新生成或重开页面重复改变状态。

## 11. 可变世界书与动态背景

- 部分世界书条目可以根据世界发展和剧情走向更新，变化会影响后续聊天和相关角色背景。
- 推荐固定/可变分类：默认固定，可变条目明确允许改变的范围；该分类与具体编辑流程待确认/设计。
- 只有实际发生或正式确定的事件才能作为事实更新；区分提议、传闻、角色主张与已验证事件。
- 不把私人聊天或未公开经历自动写成所有角色都知道的公共事实；角色上下文遵守知情范围。
- 未发送草稿、失败生成、被取消的导入与重复事件不能直接修改世界。
- 更新保留来源、时间和旧状态的追溯依据；动态修改与“再次导入同名条目保留旧内容”是不同操作，不能借导入覆盖当前剧情。
- 世界书负责设定/剧情事实，运行状态负责当前位置、日程、心情、关系；相关界面读取一致状态，不各自生成相互矛盾的版本。
- 自动新增地点及重构地图属于后续阶段；本阶段可变地点状态不能偷换为自动扩图。

## 12. 可靠性和验收

本阶段不做旧角色、旧格式兼容；App 尚未上线，不建补全/迁移模块。此决定不授权删除现有本机数据。正常使用中的新状态仍必须持久化，重开可接续，不能把“不兼容旧版”解释为“不保存状态”。

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| P2-01 | 测试时钟经过现实 10 分钟 | 当前世界经过 30 游戏分钟，其他世界不动；真机补一次实测 |
| P2-02 | 切换世界后推进，再返回 | 原世界从冻结点继续；角色、天气和消息任务无偷跑 |
| P2-03 | 关闭 App 一段时间后重开，再反复打开 | 仅当前世界按 3:1 补齐一次；关闭期间不要求通知 |
| P2-04 | 休息跨过多个日程及午夜 | 快走时钟后出现期间留言；日期、位置、事件顺序正确 |
| P2-05 | 同会话消息相隔 4:59、5:00、5:01 游戏分钟 | 4:59 不插新时间标记，后两者插入；首条/跨日有正确标记 |
| P2-06 | 重开补齐或休息留言 | 使用各自游戏发生时间；不全标为生成时间，不重复发布 |
| P2-07 | 查看地图及角色移动 | 用户/角色位置真实一致；无用户出行/赴约入口 |
| P2-08 | 卡无地图，目标世界也无地图 | 拒绝并说明原因，无联系人/会话/资源残留 |
| P2-09 | 卡无地图，目标世界已有有效地图 | 复用地图；其他必填检查通过后正常导入 |
| P2-10 | 地图无效、初始信息缺失或地点无效 | 给出具体错误，不部分导入；合法信息不因额外未确认限制被拒 |
| P2-11 | 首角色建世界、后续角色时间不同 | 首角色设定世界时间；后续适配而不重置世界，不编造共同经历 |
| P2-12 | 导入预览、资料页、鉴定依次查看 | 预览两栏目；资料页前尘往事+鉴定；此时此刻只在导入预览/鉴定出现 |
| P2-13 | 忙碌时留言，推进到空闲 | 可简短回复或暂缓，随后处理待回复，不丢失/重复 |
| P2-14 | 聊天提出并最终确认/取消约定 | 提议不直接成事实；实际达成的安排影响日程，位置无冲突 |
| P2-15 | 不发消息且关闭对应聊天页 | 当前世界角色仍可主动联系，性格/日程实际影响时机 |
| P2-16 | 天气或相关事件变化 | 同地区天气一致，相关生成引用正确；具体变化规则待定后补样例 |
| P2-17 | 事件改变关系/心情，重复处理该事件 | 鉴定反映真实变化，普通页隐藏；重复执行不叠加 |
| P2-18 | 更新可变条目与角色当前背景 | 后续上下文使用新事实，固定范围不被误改，私人信息不全员传播 |
| P2-19 | 生成过程中切世界、插话、失败重试 | 旧结果不越权发布；正式历史、待回复和世界状态保持一致 |
| P2-20 | 补齐/休息处理中断、无网或模型失败 | 不假报完成、不空消息、不重复更新；可按设计恢复 |
| P2-21 | 阶段 1 关键路径回归 | 导入整体成功/取消、唯一会话、分段、插话、引用仍正确 |

自动化验证规则边界、时间/事件顺序与去重；界面测试验证入口和显示；实际模型验证自然交流与事实理解；真机验证关闭/重开、快钟及多角色留言。以上用例均为待执行，文件检查不能替代实机或用户验收。

## 13. 建议与待定项（不冒充已确认）

| 事项 | 当前建议/缺口 | 下一步 |
