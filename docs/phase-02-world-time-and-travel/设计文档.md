## 1. 本轮范围与默认选择

实现需求 P2-01 至 P2-21。保留现有聊天、引用、分段、角色世界归属及世界用户资料；不清数据，不做线下互动、后台执行、通知、旧卡补全、提交或发布。原始 PNG 只读，改造副本另存。

以下是本轮可调整的实现默认值，不称为用户已确认产品规则：天气采用按世界种子/区域/游戏时段一致的模拟天气；好感 0—100，心情强度 0—100；世界日期独立，钟点跟随手机现实时间；长期离线按事件逐步处理，可暂停和重试，不截去经过时间。前尘往事保留公开身世，不自动追加私人经历。条目默认固定，只有明确标记可变且有实际事件依据才可更新。重新生成/删除消息只影响表达，不回滚已发生世界事实。

## 2. 数据与时钟

core:model 持有可序列化的地图、角色初始化、时间段日程、世界快照、状态变化及确定性规则；不依赖 Android。data:settings 原子保存世界集合，提供可观察快照；app 的世界运行器在应用前台工作，负责角色生成和将已提交事件投递到原会话。

每个世界保存已结算时间 now 和目标时间 target。年月日由世界维护，新世界使用首角色的初始日期；时分秒替换为手机当前本地钟点。每次计时根据上次现实日期与当前现实日期之间的天数推进世界日期，再对齐钟点，因此跨午夜、离线多天、多个不同年代世界仍保持同钟点。内部沿用本地日期编码，不是 UTC 瞬时时间。只有当前世界执行事件，重开/切回按实际经过时间补齐。

当前运行存档只接受 version=2，不迁移旧版、不自动生成旧版备份。系统时区改变或时钟回拨时自动校准当前运行点，保留联系/移动的剩余时长与已提交历史，具体约定的日历日期保持不变。

2026-11-06 提示体验修正：移除 clockWarning 的生成、持久化与界面展示；正常校时静默执行，实际处理失败仍走运行器错误提示及重试入口。用户明确无需旧版兼容，删除先前的 v1 升级分支和相应迁移测试。指定测试卡 PNG/JSON 只读检查一致，没有加速规则，本次无需改卡或删除联系人。

正常界面不显示“钟点与现实同步”等运行机制说明；移除首页说明行及对应中英文文案，只保留日期钟点、实际错误和离线补齐操作。

消息仍使用原 ts 作稳定存储键；世界记录保存 sessionId/ts 对应的游戏时间。发布前先持久保存发件记录，重复投递沿用同一 ts，聊天写入成功后清除发件记录。世界状态与事件游标一次保存，避免重试加两次好感。鉴定纯读取快照。

## 3. 角色卡与地图协议

项目专用扩展为 data.extensions.momoly_life，version=1，包含 initialTime（ISO 本地日期时间）、initialLocation（地点 id）、background（此时此刻）、history（前尘往事）、可选 schedule（每日区间）、初始关系和情绪。明确这是 Momoly 扩展，不是通用角色卡标准。

地图是世界书必备条目，extensions.momoly.kind=map，content 为 JSON：version、places（id/name/region/x/y）、routes（from/to/minutes）、userLocation、climates。路径时间明确给出；坐标只用于示意排布。已存在世界优先使用现有地图，相同 id 内容冲突拒绝，不自动覆盖或扩图。缺图、非法时间、缺背景、无效位置在任何导入写入前拒绝。

导入先读取和验证，再按已有世界当前时间/公共事实适配背景并显示此时此刻、前尘往事。确认后写资源，角色 JSON 作为导入提交标记。世界从已提交角色初始化，失败不会留下运行人物；取消不写世界状态。新世界保留首角色初始日期并对齐现实钟点；后续角色使用已有世界日期及当前现实钟点。

scenario 保持作者原文，不随时间适配重写；模型装配仍接收原场景，动态状态由 lifePrompt 单独提供，并以当前世界钟点为准。避免原关系、背景条件被通用运行状态吞掉。

首页联系人与抽屉预览复用 RegexEngine 的显示用称呼替换，读取该角色所在世界的用户名；不改消息存储，也不在预览执行修改变量的宏。

已有世界的适配采用当前日期、有效位置、原公开身世与已提交公共世界书事实组合，不另调模型编造入场经历。过期的具体日期日程不再启用；保留 first_mes 与 alternate_greetings，首次创建会话由 ConversationOps 写入开场白，已有会话直接复用，不重复插入。原场景和初始化信息另存于 momoly_original_entry。每日作息仍保留。地图当前要求与目标地图完全一致，未实施地图合并。

## 4. 日程、主动聊天和世界变化

日程是半开时间段 [start,end)，每日模板加具体日期的约定覆盖。不同地点之间插入按路线耗时的移动段；冲突和不可达路径拒绝。无模板时以初始位置自主安排，随后模型可提出有效日程，不捏造固定职业任务。

生成使用当时的时间、天气、活动、位置、真实情绪/好感和已知事实；普通用户输入、忙后补答、主动联系和离线补算走同一世界运行器。保留原会话，禁止伪造用户消息。不可通信时持久记录待答；简短通信限制回复；空闲后先处理未答。主动机会按性格表达倾向和当前活动产生，模型可以选择不发，不设全员低每日条数限制。

模型返回结构化的候选正文和状态变化。代码只允许修改该角色的情绪/关系/未来日程和已声明可变条目；提交前检查世界/输入版本、时间、地点、权限、证据和长度。失败、过期生成、未发送内容不更新。私聊产生的事实默认角色私有；公共条目变化必须有公共事件依据。每次变化保留来源消息、游戏时间、原因和旧值。

生成复用既有全局规则书、关联世界书、预设和发送侧正则。部分聊天预设强制只返回正文：遇到完整的纯文本回复时，另发一次不带角色扮演预设的状态核对请求；核对成功再发布正文。格式损坏的 JSON 不当作聊天正文发送。通常一次事件一次模型调用，触发纯文本兼容时两次；任一调用失败均保留待处理进度，用户可重试。未依赖额外服务器或新的商业接口。

可变条目使用 extensions.momoly 的 kind=fact、id、mutable、scope（public/self）、可选 binding。公共天气由 weather:地点id 绑定更新；角色活动由 activity:self 绑定更新；没有绑定的 self 条目可据实际发出的聊天变化。公共剧情不会仅凭私聊自动传播；当前没有公共故事事件生产者，因为线下剧情后续开发。变更写回实际世界书，同时保留运行存档中的来源与旧值。日程时间按分钟表示，跨午夜用两个区间，具体日期覆盖每日模板；固定区间不能被聊天约定替换。

长离线单批处理 12 次模型事件后，若仍有超过一小时积压，暂停并提供继续入口；不是每天 12 条上限，不截断目标时间。切世界保存离开世界的进度，所有世界目标继续跟随现实时间，尚未生成的历史事件保留到返回后再处理，未选中期间不会调用其模型。每次中断都不把待补齐状态显示成全部完成。

实时消息保持三秒收集输入、分段及每字 0.5—1 秒发布节奏；离线留言直接批量投递。用户插话使旧生成失效，尚未发出的内容留作草稿，不进入已知历史。

尚有超过五分钟历史积压时，发送操作保留输入框正文，不写入错误提示，由页面内“正在刷新”说明当前状态，避免把当下用户消息排在尚未发布的历史留言之前。正常忙碌中的用户留言照常保存、随后补答。

## 5. 界面

2026-11-06 区域导览：按地图已有 region 分组，由地点原始纵向顺序组织区域及行，横向位置优先沿用原有相对位置；同排过近时均匀排开。区域、文字、地点和连线共用测量后的坐标，按实际字体与姓名高度留空；无区域名时不编造城市名称。区域底色使用适应明暗主题的低饱和绿/暖灰，普通节点为空心小圆，人物名牌和占用点使用强调色。页头压缩为世界名、日期及当地天气；底部常驻一块选择反馈位置，选中连线才显示路线名和耗时，并支持关闭和系统返回。保持原生 Compose，不引入网页图形库。

2026-11-06 地图精简：地图页使用独立拓扑组件，移除角色卡片、资料入口、重复位置与路线清单。地点和文字共用坐标，地名在下、人物名在上，有人所在地点用主题强调色高亮；同地多人合并显示，用户名称读取当前世界资料。连线提供点击区域，选中后高亮并弹出该路线耗时，切换世界清除选择。天气集中放在地图页，首页仅保留运行状态。地图空间不足时可滚动，文字按实际测量高度排放。

底部新增地图，展示地点、路线、用户与角色标记及天气。首页显示世界日期与现实钟点；不再提供休息按钮、时长选择、快钟和结束弹窗。2026-11-07：首页、聊天、地图和鉴定的正常补齐统一只显示“正在刷新”，移除处理时间及正常刷新时展开的操作按钮；首页与聊天的实际暂停/失败保留原因与继续入口，此时不同时显示正在刷新。角色资料从联系人菜单/聊天标题进入，仅列前尘往事和鉴定入口；鉴定含此时此刻、日程、心情、好感度。

同会话首条、跨日以及相邻已发消息游戏时间差至少五分钟显示游戏时间。原实际时间只用于存储与排序，不冒充游戏时间。
