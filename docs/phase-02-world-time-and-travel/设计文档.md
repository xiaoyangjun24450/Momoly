# 阶段 2 设计文档：世界运行与角色生活

> 更新：2026-11-04。用户已授权实现阶段二、改造指定 PNG 卡并测试。状态：主要功能已实现，自动化与真机验证见第 7 节；尚未经用户验收。

关联：[需求文档](需求文档.md) · [调研文档](调研文档.md)。本文件取代此前含用户出行、占位时间及通知验证的旧草案。

## 1. 本轮范围与默认选择

实现需求 P2-01 至 P2-21。保留现有聊天、引用、分段、角色世界归属及世界用户资料；不清数据，不做线下互动、后台执行、通知、旧卡补全、提交或发布。原始 PNG 只读，改造副本另存。

以下是本轮可调整的实现默认值，不称为用户已确认产品规则：天气采用按世界种子/区域/游戏时段一致的模拟天气；好感 0—100，心情强度 0—100；休息提供 30 分钟、2/8/24 小时；长期离线按事件逐步处理，可暂停和重试，不截去经过时间。前尘往事保留公开身世，不自动追加私人经历。条目默认固定，只有明确标记可变且有实际事件依据才可更新。重新生成/删除消息只影响表达，不回滚已发生世界事实。

## 2. 数据与时钟

core:model 持有可序列化的地图、角色初始化、时间段日程、世界快照、状态变化及确定性规则；不依赖 Android。data:settings 原子保存世界集合，提供可观察快照；app 的世界运行器在应用前台工作，负责角色生成和将已提交事件投递到原会话。

每个世界保存已结算时间和目标时间。当前世界以单调时钟计量，跨重启以墙上时钟补齐，现实经过量乘 3；切换时结算时间锚点，其他世界冻结。时钟倒退不倒流，异常显示说明。事件逐个提交后才前移已结算时间，模型失败保留未处理目标。重开补齐由前台执行，非后台执行。

消息仍使用原 ts 作稳定存储键；世界记录保存 sessionId/ts 对应的游戏时间。发布前先持久保存发件记录，重复投递沿用同一 ts，聊天写入成功后清除发件记录。世界状态与事件游标一次保存，避免重试加两次好感。鉴定纯读取快照。

## 3. 角色卡与地图协议

项目专用扩展为 data.extensions.momoly_life，version=1，包含 initialTime（ISO 本地日期时间）、initialLocation（地点 id）、background（此时此刻）、history（前尘往事）、可选 schedule（每日区间）、初始关系和情绪。明确这是 Momoly 扩展，不是通用角色卡标准。

地图是世界书必备条目，extensions.momoly.kind=map，content 为 JSON：version、places（id/name/region/x/y）、routes（from/to/minutes）、userLocation、climates。路径时间明确给出；坐标只用于示意排布。已存在世界优先使用现有地图，相同 id 内容冲突拒绝，不自动覆盖或扩图。缺图、非法时间、缺背景、无效位置在任何导入写入前拒绝。

导入先读取和验证，再按已有世界当前时间/公共事实适配背景并显示此时此刻、前尘往事。确认后写资源，角色 JSON 作为导入提交标记。世界从已提交角色初始化，失败不会留下运行人物；取消不写世界状态。首角色初始化时间，后续角色不重置世界。

已有世界的适配采用当前日期、有效位置、原公开身世与已提交公共世界书事实组合，不另调模型编造入场经历。过期的具体日期日程不再启用；旧开场不自动发送，原开场、场景和初始化信息保留于 momoly_original_entry。每日作息仍保留。地图当前要求与目标地图完全一致，未实施地图合并。

## 4. 日程、主动聊天和世界变化

日程是半开时间段 [start,end)，每日模板加具体日期的约定覆盖。不同地点之间插入按路线耗时的移动段；冲突和不可达路径拒绝。无模板时以初始位置自主安排，随后模型可提出有效日程，不捏造固定职业任务。

生成使用当时的时间、天气、活动、位置、真实情绪/好感和已知事实；普通用户输入、忙后补答、主动联系、休息和离线补算走同一世界运行器。保留原会话，禁止伪造用户消息。不可通信时持久记录待答；简短通信限制回复；空闲后先处理未答。主动机会按性格表达倾向和当前活动产生，模型可以选择不发，不设全员低每日条数限制。

模型返回结构化的候选正文和状态变化。代码只允许修改该角色的情绪/关系/未来日程和已声明可变条目；提交前检查世界/输入版本、时间、地点、权限、证据和长度。失败、过期生成、未发送内容不更新。私聊产生的事实默认角色私有；公共条目变化必须有公共事件依据。每次变化保留来源消息、游戏时间、原因和旧值。

生成复用既有全局规则书、关联世界书、预设和发送侧正则。部分聊天预设强制只返回正文：遇到完整的纯文本回复时，另发一次不带角色扮演预设的状态核对请求；核对成功再发布正文。格式损坏的 JSON 不当作聊天正文发送。通常一次事件一次模型调用，触发纯文本兼容时两次；任一调用失败均保留待处理进度，用户可重试。未依赖额外服务器或新的商业接口。

可变条目使用 extensions.momoly 的 kind=fact、id、mutable、scope（public/self）、可选 binding。公共天气由 weather:地点id 绑定更新；角色活动由 activity:self 绑定更新；没有绑定的 self 条目可据实际发出的聊天变化。公共剧情不会仅凭私聊自动传播；当前没有公共故事事件生产者，因为线下剧情后续开发。变更写回实际世界书，同时保留运行存档中的来源与旧值。日程时间按分钟表示，跨午夜用两个区间，具体日期覆盖每日模板；固定区间不能被聊天约定替换。

长离线单批处理 12 次模型事件后，若仍有超过一小时积压，暂停并提供继续入口；不是每天 12 条上限，不截断目标时间。切世界先保存离开世界已经经过的目标时间，尚未生成的历史事件保留到返回该世界再处理，冻结期间不会调用其模型。每次中断都不把待补齐状态显示成全部完成。

实时消息保持三秒收集输入、分段及每字 0.5—1 秒发布节奏；休息和离线留言直接批量投递。用户插话使旧生成失效，尚未发出的内容留作草稿，不进入已知历史。

休息未结束或尚有超过五分钟历史积压时，发送操作保留输入框正文并提示先完成补齐，避免把当下用户消息排在尚未发布的历史留言之前。正常忙碌中的用户留言照常保存、随后补答。

## 5. 界面

底部新增地图，展示地点、路线、用户与角色标记及天气。首页显示真实日期时间；休息入口打开时长选择，处理中只显示快钟与处理状态，失败可重试/稍后继续，成功弹出本次留言列表。角色资料从联系人菜单/聊天标题进入，仅列前尘往事和鉴定入口；鉴定含此时此刻、日程、心情、好感度。

同会话首条、跨日以及相邻已发消息游戏时间差至少五分钟显示游戏时间。原实际时间只用于存储与排序，不冒充游戏时间。
