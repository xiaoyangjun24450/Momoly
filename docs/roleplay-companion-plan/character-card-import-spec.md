# 角色卡与世界书格式校验：待调研

状态：调研占位文档，不是已确定的准入规范；本次不开展调研或实现校验器。  
关联：[阶段 1](phase-01-contacts-and-chat.md)、[产品需求](../roleplay-companion-requirements.md)。

## 1. 已明确的规则

- 导入 PNG 角色卡，需要能够读取其中的角色数据。
- 角色卡必须附带世界书；世界书缺失或没有名称时，校验不通过，不能导入。
- 根据角色卡的世界书名称选择所属世界，同名世界书归入同一个世界。
- 合并世界书条目时，同名条目保留旧条目。
- 校验失败应说明具体原因，不部分添加联系人或合并世界书。

## 2. 暂不确定的内容

角色卡和世界书的最低内容清单、必填字段、字段类型、扩展结构，以及合并后的具体关联校验规则，均留待后续调研。

此前草拟的字段表、扩展字段、地点最低数量、作息格式、往返路径要求和 JSON 示例已撤下，不作为当前导入拒绝条件或验收标准。

## 3. 后续调研范围

| 调研方向 | 需要回答的问题 |
| --- | --- |
| 现有格式与样例 | 当前 APP 能读取哪些角色卡和世界书格式？实际样例通常提供哪些信息？ |
| 角色信息完整性 | 身份、性格、起始关系等信息可能出现在哪里？哪些必须显式提供，哪些可以复用已有内容？ |
| 世界运行信息 | 地点、场景、出行方式、耗时和时间信息如何表达？是否需要额外结构，如何兼容现有世界书？ |
| 日程与初始状态 | 角色初始地点和日程应来自角色卡、世界书、运行时生成还是其他来源？哪些信息需要在导入时检查？ |
| 合并行为 | 保留同名旧条目后，哪些数据关联需要检查，如何避免因未确定的规则拒绝可用角色卡？ |
| 校验边界 | 哪些问题应阻止导入，哪些需要提示或在使用对应功能时处理？ |

以上是调研问题，不预设字段名、数据结构、最低数量或补全策略。

## 4. 调研后的交付

调研完成后，再整理有依据的最低内容清单、格式方案、兼容范围、错误反馈，以及合格和不合格样例，并据此补充阶段 1 的实现要求和验收用例。

聊天是否有活人感、线上是否只输出消息正文，继续按阶段 1 的聊天规则验收，不因格式调研延期而改变。
