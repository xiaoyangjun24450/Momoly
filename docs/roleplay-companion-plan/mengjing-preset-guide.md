# 梦鲸思客 V5：用途、配置与 Momoly 融合说明

核对日期：2026-11-02。对象是用户提供的 `梦鲸思客V5-1030-exp.json`，不是对同名预设其他版本的保证。源文件 SHA-256：`96065d1e36f4036532e532ffa12b039f07abb610f53ee2045e3af6e20668b635`。Momoly 对照基线：`3c086bb`。

## 1. 它到底干什么

角色卡规定“这个人是谁”，世界书提供“世界和人物有哪些背景”，预设规定“模型怎样读取这些材料、怎样回应、输出成什么样”。预设不是模型，不自带 API 服务，也不会单靠导入就获得长期记忆、真实世界时间或后台主动联系。

这份梦鲸思客主要用于**与用户共同写长篇剧情**。它把模型定位成叙事者“思客”，用多组提示词选择文风、人称、用户扮演对象、能否代写用户行动、输出篇幅、剧情分析和附加栏目，再用正则与酒馆助手脚本处理结果。

这份导出有 **122 个提示条目、主顺序组启用 44 项、28 条正则和 6 个启用的酒馆助手脚本**。其中有空标题和角色／历史占位条目；这些数字不等于 122 项都发送给模型，也不等于全部附件都是每轮提示词。

文件当前选择：Gemini 方向的身份和预填充、梦白话、第三人称、转述抢话、温和叙者、动态长篇约 1000～2000 字、普通思考、通用角色分析、发散思维链、写作模式；还启用了思客大调查、场景信息、平行事件。它不是一份开箱即用的纯消息私聊预设。

“聊天模式”虽然关闭长篇 XML 输出协议，却仍要求输出带固定开头的分析内容，也没有完整的“只作为当前角色发消息”边界。因此只把写作模式切成聊天模式，不能保证符合 Momoly 的产品要求。

## 2. 当前项目哪里需要补强，本轮怎样处理

2026-11-04 更新：保留梦鲸经典段落，另参考用户提供的 DSH 卡调整短回应、语气助词、接梗与重复句式。具体改动和待执行试聊见 [默认资源说明](default-online-chat-resources.md)。下表继续记录梦鲸部分的取舍。

原有默认资源已覆盖纯消息、口语、避免机械追问，但对“谁知道什么”只有简短要求，对人物自主性、计划与事实的区别、连发更正和未发草稿缺少具体约束。

本轮重新编写并融合这些思路，不整段复制原预设的运行协议：

| 原预设可借鉴部分 | Momoly 落地方式 |
| --- | --- |
| 保持信息差 | 世界书明确区分客观事实、角色已知、推测、未知；秘密要有知情途径，不能临时补造目击者或直觉。 |
| 禁止霸总、避免替用户决定 | 保留角色已有性格和关系，但不自动加占有、强迫、替用户答应或把拒绝当同意的套路。 |
| 梦白话、杀解释欲、结尾控制 | 转成适用于私聊的直接回应、减少背景倾倒、避免总结升华和固定追问；需要解释时仍答清楚。 |
| 不抢话方向 | 只生成当前角色消息，不补写用户行为、发言、感受或决定。 |
| 发送前检查 | 保留最终输出边界；版本 4 去掉逐项检查清单，避免每次闲聊都被组织成完整答复，不输出思维链或检查报告。 |

预设负责身份、材料顺序、本轮回应和最终输出边界；共用世界书负责跨角色一致的交流、关系与知情规则。当前预设内容版本为 4，共用世界书为 3；资源身份保留原 ID，避免把共用书当成另一本世界书。

保留原有温度 0.9、上下文 80000、回复上限 8192。它们不是效果保证，也不是要求回复这么长；本轮未做模型参数对比，不直接套用原文件的 200 万上下文和 3 万回复上限。

版本 3 按用户要求，将原文件“梦境思客Gemini”条目的完整正文原样放入默认开启的首条系统提示，保留《道德经》《阴符经》引文和原文解释，不再只提炼成通用规则。其后明确梦鲸为幕后的创作定位，实际发言仍是当前角色，不强制角色自称梦鲸或采用古文口吻。这是保留用户指定内容，不代表经典段落的效果已通过模型测试。

没有加入：第三人称长篇、成人内容强化、XML 正文协议、剧情调查、平行事件、数据库兼容提示、专用压缩宏、额外脚本与 HTML 美化。它们会改变当前私聊形态，或依赖 Momoly 尚未接入的运行能力。

## 3. 在 Momoly 中怎么用融合版

资源文件：

**直接随 APP 内置，用户无需导入或重新关联。** 新安装首次初始化使用融合版；旧安装在更新 APP 后，打开资源页面或加载聊天时，会按内容版本自动更新内置默认预设和全角色规则书。

- 更新保留原预设 ID、共用书固定 ID 和已改过的文件名，原来关联默认预设的角色继续使用同一关联；没有关联预设的角色继续自动使用默认预设。
- 共用书仍自动加入所有角色，不创建副本、不改变角色所属世界。
- 默认资源从旧版更新时，其正文、开关和参数替换为 APP 随包版本，包括旧版默认资源里的个人修改。用户另建或导入的独立预设、角色世界书和已有聊天不受影响。
- 已经是同一内容版本时不重复覆盖，现有编辑功能仍可使用。未来需要长期保留自定义方案时，应使用独立资源，避免与内置默认的升级混在一起。较新内容版本不会被旧 APP 降级。
- 明确选择了其他预设的角色保留原选择，同时使用新版共用规则书。

源码与构建检查不等于手机已安装更新。本轮没有操作用户手机或调用真实模型。角色卡的已有开场白是保存文本，预设不会自动改写它；其他预设、角色深度提示或叙事示例仍可能与纯消息规则冲突。

## 4. 如果要在 SillyTavern 用原版

1. 在聊天补全接口对应的“AI Response Configuration／AI 回复配置”导入原 JSON，再选择它；接口地址、密钥和实际模型另外配置。预设名称和 Gemini 条目不会替你连接模型。
2. 打开提示列表，核对当前启用项；“主要文风”“用户扮演对象”“人称”“输出模式”等选择组不要同时启用互相冲突的项。标题分隔条目本身不提供能力。
3. 写剧情选“写作模式”；整理旧剧情用“大总结模式”；暂时向叙事者提问可以用“聊天模式”。三个输出模式只开一个，切换后检查结果是否符合预期。
4. 原版使用 `{{压缩相邻消息::lora_constant}}`、`{{压缩相邻消息::lora_key}}` 等专用宏，需要对应消息处理脚本工作。核对目标酒馆中的酒馆助手、预设脚本导入情况和脚本开关；不能因为 JSON 中有脚本就当成运行成功。
5. 先用短对话检查角色信息、世界书与历史是否进入实际请求，以及正文、分析块、状态栏是否正确处理。若出现原样宏、XML 标签或 HTML 美化代码，先排查依赖和输出处理，不用加长提示词掩盖缺失能力。

本轮没有连接实际 SillyTavern，也未核对用户的安装版本或执行附件脚本。上述是根据文件结构和官方导入／提示管理机制整理的用法，不是原版在某个宿主上的运行通过记录。官方入口与编排说明见 [Prompt Manager](https://docs.sillytavern.app/usage/prompts/prompt-manager/)。

| 数据库兼容 | 对 SP、柚月表格、柏宝书、Ruby 的输出约定做提示适配 | 全关；要实际安装并接通相应系统才可能工作。 |

“变量宏”指 `{{setvar::...}}`、`{{addvar::...}}`、`{{getvar::...}}` 这类占位表达式：先写入文风等设置，之后读取并拼到最终提示。因此把一条 `addvar` 文风独立拷走，缺少初始化和读取位置，就不一定有预期效果。本轮改成独立可读的中文规则，仅保留 `{{char}}`、`{{user}}` 人名替换。

## 6. 数值、格式字段与 Momoly 支持情况

token 是模型处理文字的计量单位，不等于汉字数。下面数值来自附件；不同模型和接口支持的字段、范围与实际效果不同。

| 字段／附件值 | 大白话与本次含义 | Momoly 当前处理 |
| --- | --- | --- |
| `temperature: 1` | 控制候选用词随机性；并非越高越聪明 | 读取，受“发送温度”开关与接口支持控制。 |
| `top_p: 0.95` | 保留累计概率达到阈值的一组候选词 | 读取并按发送开关传递；融合版保留原项目关闭发送的设置。 |
| `top_k: 0` | 限制候选词数量；0 通常表示不限制 | 读取，当前组装器仅在开启且大于 0 时发送。 |
| `frequency_penalty: 0`、`presence_penalty: 0` | 减少重复用词／反复使用已出现内容的倾向 | 读取；为 0 时当前组装器不发送。并不保证消除套路句。 |
| `repetition_penalty: 1` | 重复惩罚，1 为中性 | 读取保存，但当前请求组装没有下发它。 |
| `top_a: 0`、`min_p: 0` | 进一步筛掉低概率候选词；此处为关闭取值 | 读取保存，但当前请求组装没有下发它们。 |
| `openai_max_context: 2000000` | 声明可用上下文预算 | 影响本地预算，不能扩展服务端真实容量；须与实际模型核对。 |
| `openai_max_tokens: 30000` | 单次生成 token 上限，不是最低长度 | 读取，受发送开关控制；可能超出所用接口限制。 |
| `max_context_unlocked: true` | 放宽客户端的上下文设置限制 | 不是向服务端申请更大窗口。 |
| `seed: -1` | 没有指定固定随机种子 | 当前组装器仅在开启且非负时发送。固定种子也不是跨服务复现保证。 |
| `stream_openai: true` | 请求逐块传回生成内容 | 预设解析保留此项；Momoly 聊天气泡仍按自己的收发流程发布，不能据此保证逐字显示。 |
| `reasoning_effort: low`、`show_thoughts: true`、`verbosity: auto` | 原宿主的推理强度、思考显示和详细程度配置 | 当前预设解析器不读取这三项；Momoly 的推理选项另走请求设置，聊天界面也有自己的显示规则。 |
| `function_calling: false` | 原配置关闭工具调用 | 解析保留；附件同时保存了工具桥设置，不代表工具桥一定执行。 |
| `tool_reasoning_mode`、`tool_call_recurse_limit` | 工具推理方式与连续工具调用限制 | 当前预设解析器未读取；不会仅因导入而建立工具循环。 |
| `enable_web_search: false` | 原配置关闭服务端联网搜索 | 不是 Momoly 的联网功能开关；解析器未读取。 |
| `request_images`、`media_inlining`、图像质量／尺寸 | 图像返回、媒体打包相关选项 | 当前预设解析器未读取，不能代表应用实际多模态能力。 |
| `n: 1` | 期望生成候选数量 | 当前预设解析器未读取。 |
| `names_behavior`、`use_sysprompt`、`squash_system_messages` | 原宿主的姓名及系统消息组织方式 | 当前预设解析器未读取，不能原样迁移行为。 |
| `wi_format`、`scenario_format`、`personality_format` | 世界书、场景和性格的外层模板 | 当前预设解析器未读取这些模板字段。 |
| 新聊天／群聊／示例／续写／代写提示，prefill/postfix | 指定场景下的提示和回复前后缀 | 当前预设解析器未读取这些顶层字段；`prompts` 中的普通条目是另一条读取路径。 |
| `bias_preset_selected`、`send_if_empty` | 用词偏好方案、空输入替代文本 | 当前预设解析器未读取。 |

参数一般含义参照 [SillyTavern Common Settings](https://docs.sillytavern.app/usage/common-settings/)；具体 Momoly 行为以 `PresetParser.kt`、`PromptBuilder.kt`、服务适配器为依据。JSON 中保留一个字段，不等于该字段已经参与请求。

提示条目的结构也可以编辑：

| 字段 | 含义 |
| --- | --- |
| `identifier` / `name` / `content` | 稳定标识／界面名称／实际提示文字。改名称不是改身份；顺序表靠标识关联。 |
| `prompt_order[].order[].enabled` | 此文件中真正决定主顺序组开关的来源。Momoly 优先选 `character_id=100001` 组，条目未列入该组时禁用。 |
| `role` | 消息身份：system 是规则，user 是用户侧提示，assistant 是预置助手发言；与小说第一／三人称无关。 |
| `marker` | 角色描述、世界书、聊天历史等插入槽位；空 `content` 不一定表示无内容。 |
| `injection_position` / `injection_depth` | 按列表编排或插入历史中的位置／距离对话末尾的消息数。不要把预设位置数字与世界书位置数字混用。 |
| `system_prompt` / `forbid_overrides` | 系统预设标记／是否阻止角色卡替换相应主提示与尾部提示；不代表模型必定遵从。 |

## 7. 正则、脚本和扩展是什么

正则是按文字模式查找／替换内容的规则。附件里的 28 条包括清理 XML 外壳、处理分析块、隐藏选项／变量更新／旧摘要，以及把场景栏、选项和讨论转成 HTML。`disabled` 是关闭开关，`placement` 决定处理哪类消息，`markdownOnly` 和 `promptOnly` 区分显示或送模型的处理，`minDepth`／`maxDepth` 限制历史范围。名字写“隐藏”不代表只影响屏幕，必须看字段；例如这份文件有按历史深度改变模型所见正文／摘要的规则。

Momoly 能解析预设正则，但其渲染与正则执行环境不等于原酒馆。未经验证不能宣称 28 条均兼容，本轮融合版不使用它们。

## 8. 如何判断这次改动有没有用

自动检查能验证 JSON、开关、角色关联保留、共用书去重、人物与世界信息进入提示，以及避免角色主提示覆盖默认边界；不能判断真实模型的情商和人物表现。

真实模型验收待执行：热情与寡言角色各至少 10 轮，固定模型和采样设置，记录角色卡、输入、原始回复与屏幕表现。重点覆盖：

| 场景 | 应观察的结果 |
| --- | --- |
| 只在世界背景中写了秘密，角色没有获知渠道 | 不直接说出秘密，不凭空补造渠道。 |
| 用户连续说“明天见”“不对，后天”“先别约了” | 以最后意愿为准，不宣布赴约完成。 |
| 旧回复有未发草稿，用户已经换话题 | 不把草稿当成用户看过的话，不补发过时内容。 |
| 明确恋爱关系与初识角色分别聊天 | 已有亲密不被强行抹掉，初识也不自动恋爱化。 |
| 用户只是倾诉，随后明确求助 | 前者不灌建议，后者给出具体回答。 |
| 请求拥抱描写或状态栏 | 仍以消息回应，不生成动作旁白、XML 或假系统通知。 |
| 图书馆开放时间已知，但角色位置未知 | 不自行声称在馆或找到座位。 |

提示词不能保证每次输出都符合要求。本轮不声称已经解决所有世界书问题；关键词触发、书籍合并、时间／地点注入和长期记忆仍按原计划推进。
