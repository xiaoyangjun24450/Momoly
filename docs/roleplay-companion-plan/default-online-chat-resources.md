# 默认线上聊天预设与常驻规则世界书

更新日期：2026-11-04。内容版本：预设 4、共用世界书 3；固定资源 ID 保持不变。

当前保留“梦鲸思客 V5”的经典原文与信息差规则，并参考用户指定的 DSH 卡补充短反应、接梗、语气助词和跨轮句式变化，减少客服式展开。原版用途、开关解释、兼容性与内置更新方式见 [梦鲸预设说明](mengjing-preset-guide.md)。

| 资源 | 内容 | 使用方式 |

| [默认聊天预设](../../data/resources/src/main/assets/defaults/online-chat-preset.json) | 角色身份与提示顺序；按话头回应；短反应许可与最终消息边界 | 随 APP 内置并按内容版本更新；没有关联预设或原本关联默认预设的角色自动使用它。 |

## 2. 在 APP 中的行为

- 内置默认预设与共用规则书随 APP 打包。旧版本或缺少版本标记的默认资源自动更新为随包内容，保留原 ID 和文件名，角色关联不断开；用户无须手动导入。
- “世界书”页面会出现“Momoly 线上聊天规则（全角色）”。共用书与角色自己的世界书一起加载，但不会自动写入角色的世界书关联列表，也不参与角色所属世界的归类。
- 同一份共用书只加载一次；改名后仍按固定 ID 找到并更新。已是当前内容版本时不重复覆盖编辑；较新版本不降级。
- 从旧版升级会替换内置默认资源的正文、开关和参数，包括这些默认资源上的旧版个人修改。用户另建或导入的独立资源不覆盖。已关联默认预设 ID 的角色在加载聊天前也会触发更新。
- 内置共用书与默认预设一样保留为基础资源，不提供整本删除入口；可以通过世界书编辑器修改内容或关闭其中的常驻条目。
- 新建、导入角色沿用原有默认预设关联入口；已有未关联预设的角色在加载上下文时使用默认预设。已选择其他有效预设的角色保留选择，同时加载共用规则书。

共用书使用一条完整的常驻规则，激活概率为 100%，没有关键词、延迟或冷却限制，按 `system` 深度 0 注入。使用一条规则是为了减少预算裁剪时只剩半套要求的情况；它仍遵守应用原有的世界书预算设置。

## 3. 内容取舍与来源

线上规则根据产品要求编写；版本 3 另将用户指定的“梦境思客Gemini”完整正文作为默认开启的首条系统提示原样保留，包含《道德经》《阴符经》引文及原文解释。后续主提示将梦鲸定位为幕后创作身份，实际发言仍由当前角色承担。

- 用户提供的 `梦鲸思客V5-1030-exp.json`：提炼“保持信息差”“禁止霸总”“杀解释欲”“结尾控制”和不抢话方向，重新写成独立的线上聊天规则；不采用思客作为聊天发言者，不引入长篇 XML 协议、分析块、成人内容强化、酒馆助手脚本或专用压缩宏。附件来源指纹和逐组配置解释见 [梦鲸预设说明](mengjing-preset-guide.md)。

- [MaiBot 人设协议](https://github.com/Mai-with-u/MaiBot/blob/c6429547af711555e3d4d1b8d04b413572cb616c/docs/personality-import.md) 与 [回复模板](https://github.com/Mai-with-u/MaiBot/blob/c6429547af711555e3d4d1b8d04b413572cb616c/prompts/zh-CN/maisaka_replyer.prompt)：借鉴人格与表达风格分开、承接具体对话、中文口语与减少机械追问的思路，不采用固定论坛口吻或刻意错字。
- [EchoText](https://github.com/mattjaybe/SillyTavern-EchoText/blob/35a7940f77691807be08c4e2e153118341a90c6e/lib/config.js)：借鉴角色私聊定位和清楚的身份、上下文组织；不覆盖角色原本性格。
- [RPG-Phone](https://github.com/tavern-rpg-suite/RPG-Phone/blob/5d3df0d5bf30b3e6619c5b7190bf2d8c4473df01/index.js)：借鉴短信正文、少量自然消息与禁止旁白；不使用姓名前缀、固定恋爱主题、跨世界手机或模拟媒体事件。
- [Sudachi](https://github.com/LimeBlogs/Sudachi-Next/blob/c62174f6ab6ca2a38115956e1d70a8c337c26f12/Sudachi-Next-Preset.json)：借鉴中文聊天与反全知方向；不引入动作、内心描写或禁止具体数字的文风规则。
- [AIRI 消息分段](https://github.com/moeru-ai/airi/blob/9e7917d9c660f4e8e05d3c04a5f71fe316c39b49/integrations/telegram-bot/src/prompts/message-split-v1.velin.md)：借鉴完整意思优先、仅在自然停顿时拆分的原则。

## 4. 目前的边界

2026-11-04 内容调整：

- 预设按求助、分享、玩笑、确认区分回应，允许一次短反应完成交流；不强制补解释、建议或追问。尾部去掉逐项检查清单，保留纯消息边界。
- 世界书加入语气助词、省略、重复音节及接梗方式；对“倒是”“就是”限制的是跨轮反复套用，不设禁词、不用正则删除。
- 用分享成果、弄懂操作、玩笑、确认、被夸、认真低落六类例子代替主要由安慰构成的示例；样例按语境和人物选择，不作为关键词触发的固定答案。
- 保留知情范围、关系分寸、纯消息、草稿与更正处理；经典段落逐字保留。语气词、表情、短回复不设固定比例，不强制所有角色使用网络黑话。
- 两份资源各自升版，通过原有机制更新旧默认，ID 和角色关联保留；其他独立预设与世界书不替换。

参考材料为用户提供的 DSH 卡中的“大肥鱼_人设卡_私聊版 (1).txt”“大肥鱼群（吧）友 V1.0（攻击力较弱）.docx”和“贴吧怼人型ai人格.txt.txt”。仅提炼口语碎片、接话茬和情境区分，不复制其固定鲸鱼身份、主人／女友关系、强制怼人、固定消息条数、表情比例或联网承诺。没有把参考文件打包进 APP。

分气泡代码未改：整次回复只有一个短反应可以保留，但多段回复里的不足 3 字片段仍会与邻段合并。这是显示规则，不以提示词宣称它已经改变。

规则已经接入上下文，但提示约束本身不能保证模型每次都无旁白。角色卡中直接展示的开场白及备选不会因此自动改写；流式发布和生成结果的程序检查也不在这次资源接入改动内。

默认预设锁定主提示和尾部提示，默认关闭角色示例，减少原有叙事格式的影响；用户仍可以在编辑器中调整。角色描述、深度提示及其他预设若含冲突指令，仍需用真实模型检验效果。

后续质量验收继续使用热情、寡言两种角色，各不少于 10 轮连续对话，并覆盖邀请见面、带标记与无标记动作、情绪自述和已知状态自述。本次尚未完成真实模型质量验收。

版本 2 增加的规则仍属于提示约束，不代表已实现长期记忆、世界时间、日程或程序性的旁白拦截。发送节奏和气泡拆分由现有 APP 流程负责；预设只要求自然组织正文。

## 6. 本轮真实模型试聊清单（待执行）

使用同一模型与参数，对活泼、寡言、严肃三类角色分别比较修改前后；采用相同的起始聊天历史，避免旧回复风格和随机差异被当成规则效果。固定输入可重复试几次，不用单次命中判定成功。以下是验收素材，不是已执行的测试。

| 场景与输入 | 观察点 |
| --- | --- |
| “哦，原来是在这里点”“懂了懂了” | 可以简短确认，不重新讲解、不服务式收尾；不要求必须用某个词。 |
| 分享“我居然一遍过了” | 能自然庆祝或感叹，允许“666”等短回应，也允许人物自己的等价表达，不自动分析成绩。 |
| 明显玩笑“我宣布今天开始当咸鱼” | 接住玩笑，不解释梗或给休息建议，不虚构现实事件。 |
| 连续几轮含“你倒是……”“就是……”的历史，再换话题 | 新回复不习惯性套相同句式；“给我倒杯水”“我就是想见你”仍能正常理解。 |
| 热情／严肃角色面对同一份消息 | 助词、口吻有差异，不全部撒娇或群友化，不逐句机械加“呀”。 |
| 认真求助或说明情绪低落；随后说“别开玩笑了” | 正面处理真实需要并收起玩笑，不以短回应为借口敷衍，不重复问已说明的原因。 |
| 用户改约、撤回，或原回复尚有未发送草稿 | 以最新明确意愿为准，不宣布赴约完成，不把草稿当成已说过的话。 |

记录原始模型输出和实际气泡，区分模型没生成短回应与应用合并短片段。评价接梗是否贴题、重复句式是否减少、短回应是否适时以及角色是否一致，不用“666 出现越多越好”作为验收标准。未调用真实模型前，不声称本轮已解决接梗或客服味问题。
