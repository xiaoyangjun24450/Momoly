# 阶段 4：主动联系与后台通知

前置阶段：[阶段 3](phase-03-stories-and-memory.md) 验收通过，阶段 2 的后台通知路径验证完成。  
状态：计划，尚未实现和验收。  
关联：[总计划与统一验收素材](README.md)、[产品需求](../roleplay-companion-requirements.md)。

## 1. 阶段目标和可视化结果

让角色能够依据性格、日程、记忆和约定主动联系用户，并在用户关闭 APP 后继续执行符合条件的消息任务和通知。

完成后应能看到：没有用户新消息时出现的角色主动消息、会话列表更新和未读状态、系统通知、点击通知后打开的原会话。APP 不提供免打扰，符合状态规则而产生的聊天新消息始终通知。

## 2. 功能模块

### 2.1 主动联系安排（模块 9、5）

- 输入：角色性格、日程、游戏时间、当前世界与场景状态、最近联系记录、约定和相关记忆。
- 输出：是否联系、联系原因、计划联系时间、交给聊天模块的生成请求，以及后续检查安排。
- 具体功能：无需用户先发消息也能触发联系；频率依据角色卡性格；约定、共同经历等提供话题和时机。世界冻结、角色状态和同场景线下互动限制优先于联系计划。
- 例子：热情的林夏空闲时愿意分享近况，寡言的沈言主动联系较少，但临近约定时间也可以主动确认。两人不套用同一套固定联系频率。

### 2.2 主动消息生成与唯一会话接入（模块 6、8、11）

- 输入：主动联系请求、目标角色、角色记忆、世界状态、原聊天历史。
- 输出：与联系原因相关的角色消息、原会话中的新记录、更新的预览和未读状态、必要的记忆更新。
- 具体功能：复用已有生成能力；主动消息与被动回复写入同一个角色会话；不需要伪造一条用户消息来触发。生成内容服从角色实际经历和已知信息，沿用阶段 1 的活人感预设及纯消息检查，不发布动作、旁白或内心独白。
- 例子：林夏在借书后主动发来“你借我的那本红色封面的书我开始看了”，消息出现在林夏原会话里，用户无需先询问。

### 2.3 后台任务执行与状态检查（模块 12、3、5）

- 输入：保存的到期联系或待回复任务、当前世界、游戏时间、角色活动、故事状态，以及阶段 2 确定的后台运行方式。
- 输出：任务执行结果、完成后交给聊天模块保存的消息、暂停或等待继续的任务状态。
- 具体功能：任务不依赖聊天页面保持打开；后台沿用同一套游戏时间和角色状态规则。执行前以及生成完成准备提交时检查世界和场景；冻结世界不执行联系，恢复后依据保存的世界时间和计划继续；已完成任务不重复发送。
- 例子：用户关闭 APP 后，校园世界的林夏在空闲时处理一条到期联系。若用户已切换到奇幻世界，校园世界冻结，林夏的任务不能继续产生消息。

### 2.4 系统通知与会话跳转（模块 12、6）

- 输入：已经保存的新角色聊天消息、角色和唯一会话信息、通知点击操作。
- 输出：带有角色名称和消息预览的系统通知、对应会话中的未读状态、点击后打开的原会话。
- 具体功能：对已保存的聊天新消息发出通知；本阶段不提供免打扰设置；点击通知进入对应角色已有会话。通知不另行生成第二条消息，不指向尚未保存的草稿。
- 例子：锁屏收到“林夏：你现在方便吗？”的通知，点击后打开林夏原会话，能看到同一条消息和此前聊天历史。

### 2.5 联系任务状态与去重（模块 9、12）

- 输入：已保存的联系安排、任务完成状态、聊天消息、世界和角色状态。
- 输出：重新进入 APP 后一致的任务和会话状态。
- 具体功能：重新打开 APP 后继续未完成的有效任务；已发出的消息不因重新加载而再次生成或重复写入；世界切换或故事开始后，已有计划要遵守新的状态。
- 例子：林夏的消息已经收到并保存，用户反复从通知栏和桌面打开 APP，聊天记录中始终只有这一条消息。

## 3. 阶段内执行顺序

1. 在 APP 打开时验证主动联系安排，确认性格、日程和记忆实际影响触发。
2. 将主动请求接入已有聊天生成、保存和共享记忆流程。
3. 接入阶段 2 已验证的后台运行方式，复用相同业务规则。
4. 完成通知、未读状态、通知跳转和任务恢复。
5. 在真实目标设备分别验证前台、后台、锁屏、划掉任务列表等场景。

验收应明确“关闭 APP”的场景。不能只验证退到桌面，就将划掉任务列表或其他运行场景一并标为通过；系统强制停止需要单独记录其行为和交付边界。

## 4. 完成后如何验收

准备：目标设备已允许通知；模型服务可用；按阶段 2 的时间规则安排可到期任务。主动联系用例使用实际性格和日程规则，验收记录可保存联系原因与计划时间，不要求把内部调度信息展示给普通用户。

| 编号 | 操作步骤 | 应看到的结果与通过标准 |
| --- | --- | --- |
| P4-01 | 保持当前世界运行，不发送用户消息，等待或推进到联系时机。 | 角色主动消息出现在原会话，会话列表和未读状态更新；没有伪造的用户发言。 |
| P4-02 | 在可比较的空闲时间内观察林夏与沈言的联系安排和实际结果。 | 性格实际影响安排；记录能解释两者差异。不能仅凭一次随机回复认定性格控制已生效，也不以两人措辞不同代替频率差异。 |
| P4-03 | 完成借书故事后，让相关联系任务到期。 | 主动消息能使用真实借书经历；未获知此事的角色不会引用私人细节；聊天气泡和通知预览都是消息正文，没有动作或旁白。 |
| P4-04 | 在角色忙碌时触发检查，再推进到其允许回复的时段。 | 消息不绕过角色状态；到合适时机可以联系或回复，重复检查不生成重复消息。 |
| P4-05 | 让林夏参与线下故事，再触发主动联系检查。 | 林夏不会同时从聊天窗口发消息；同场景其他角色遵守相同规则。 |
| P4-06 | 切换到奇幻世界，让校园角色原计划的时间在现实中经过。 | 校园时间保持冻结，校园角色没有新消息和通知；返回校园后按原世界的时间继续调度。 |
| P4-07 | 分别退到桌面、锁屏、划掉任务列表，等待有效任务到期。 | 按目标交付场景收到真实角色消息通知；每个场景单独记录设备、条件、实际延迟和结果，不能以重新打开 APP 后才补发代替关闭期间的通知。 |
| P4-08 | 点击一条通知。 | 进入对应角色的唯一会话，消息已存在，原聊天历史保留，不创建新会话。 |
| P4-09 | 收到通知后多次重新打开 APP 或触发任务检查。 | 消息没有重复生成、重复写入或重复通知；会话和任务完成状态一致。 |
| P4-10 | 主动生成进行中切换世界，或使目标角色进入同场景故事。 | 生成结果在提交时仍受当前状态限制，不能在已冻结世界或被暂停的聊天中继续发出。 |
| P4-11 | 分别接收普通角色回复和主动消息，检查通知设置。 | 两类聊天新消息都遵守始终通知要求；APP 没有免打扰时段或静默开关。 |

## 5. 验收交付物

- 主动消息、会话列表未读状态、系统通知和通知跳转的截图或录屏。
- 各关闭场景的设备、系统、运行条件和实际到达情况记录。
- 性格影响联系安排、状态阻止不合适联系、消息不重复的验证记录。
- P4-01 至 P4-11 的实际结果，以及前三阶段关键路径回归结果。

通过条件：主动联系真实受性格、日程、记忆和世界状态控制；约定的关闭场景能收到通知并回到原会话。未完成的后台场景必须保留为未通过项。此时可以开始阶段 5。
