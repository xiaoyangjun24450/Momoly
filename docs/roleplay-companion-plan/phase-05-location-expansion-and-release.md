# 阶段 5：地点拓展与整体验收

前置阶段：[阶段 4](phase-04-proactive-messages-and-notifications.md) 验收通过。  
状态：计划，尚未实现和验收。  
关联：[总计划与统一验收素材](README.md)、[产品需求](../roleplay-companion-requirements.md)。

## 1. 阶段目标和可视化结果

让 agent 生成的新地点真正进入现有世界，能够选择出行方式、消耗时间前往并展开故事。随后验证从导入到通知的完整流程，以及线上消息与线下叙事的模式边界。

完成后应能看到：地点拓展入口、新地点生成结果、更新后的地点列表、可执行的出行方式和耗时、新场景故事，以及结束故事后带着记忆继续进行的自然聊天。

## 2. 功能模块

### 2.1 地点拓展 agent（模块 10、11）

- 输入：用户的地点拓展请求、当前世界设定、已有地点和出行信息。
- 输出：新地点名称与场景描述、与已有地点的连接、可用出行方式和相应游戏内耗时。
- 具体功能：生成符合当前世界的地点信息；使用后续调研确定、并已在阶段 2 接入的表达方式；给出连接已有地点的出行信息、方式和耗时。具体字段结构见 [待调研事项](character-card-import-spec.md)。仅有一段场景描写而没有出行信息，不构成可使用的新地点。
- 例子：用户请求“在校园里增加一家靠近图书馆的咖啡馆”，agent 生成咖啡馆场景，并给出从图书馆前往的出行方式和耗时。验收使用实际生成并保存的数据，不强制模型输出某个固定分钟数。

### 2.2 新地点接入世界与出行（模块 2、4）

- 输入：agent 生成的地点与移动信息、当前世界已有条目和地点数据。
- 输出：合并后的世界书和地点列表、可执行的路线、新地点的持久化记录。
- 具体功能：生成结果符合既定数据格式后写入当前世界；沿用同名条目保留旧条目的规则；新增路线可被原出行模块使用；不改变其他世界。地点名称冲突时不能悄悄覆盖旧内容。
- 例子：咖啡馆写入校园世界后，在地点列表中可见。用户选择“从图书馆步行前往”，界面显示保存的耗时，进入路上状态，并在足够的游戏时间后到达。

### 2.3 新场景中的角色与故事（模块 5、6、7、8）

- 输入：新增地点、角色日程与约定、用户和角色的实际出行结果、共享记忆。
- 输出：符合位置和日程的见面结果、新地点的线下故事、后续聊天可使用的共同经历。
- 具体功能：新地点使用既有的约定、日程、出行和故事流程；角色也需要有合理的位置变化，不能因为地点生成完成就自动出现在那里。故事结束后的记忆进入原聊天。
- 例子：用户约林夏空闲时去新咖啡馆，双方完成相应移动后进入故事；在咖啡馆聊到上次借的书，角色能够衔接旧记忆，并在之后聊天中记得这次见面。

### 2.4 完整用户流程回归（全部模块）

- 输入：统一角色卡、完整功能版本、实际模型服务和目标设备。
- 输出：覆盖全部需求的验收记录、可安装交付版本、实际存在的功能限制或未通过项。
- 具体功能：贯通已确定的导入校验、世界合并、有角色口吻的纯消息聊天、时间、出行、日程、多人故事、共享记忆、快穿冻结、主动通知和地点拓展；检查状态一致，线上不会残留线下叙事。
- 例子：添加林夏后聊天约图书馆见面，途中继续聊天，与林夏和沈言经历借书故事；结束后快穿并返回，随后收到林夏主动消息；再生成咖啡馆并完成第二次见面，回到聊天时仍只显示自然的消息正文。

## 3. 阶段内执行顺序

1. 接入地点生成任务，使其输出满足现有世界设定和出行格式。
2. 将新增内容合并到世界书，贯通列表展示、移动和到达。
3. 验证角色能够在日程和位置允许时参与新地点故事。
4. 在真实目标设备执行五阶段完整回归，重点检查纯消息聊天与线下故事的边界，整理交付版本和验收记录。

## 4. 完成后如何验收

准备：在已完成前四阶段的校园世界操作，使用符合届时已确定导入规则的角色卡和可用的实际模型服务。

| 编号 | 操作步骤 | 应看到的结果与通过标准 |
| --- | --- | --- |
| P5-01 | 请求在校园世界扩展一家咖啡馆。 | 得到地点与场景描述、连接已有地点的出行方式及耗时；结果符合当前世界设定。 |
| P5-02 | 查看世界书和地点列表。 | 新地点及出行信息已保存并可见，已有地点未被无关修改，其他世界没有被加入该地点。 |
| P5-03 | 让扩展请求涉及已有同名条目，检查合并结果。 | 原条目完整保留；不存在以新生成内容覆盖旧条目的情况；结果能清楚说明哪些内容实际被添加。 |
| P5-04 | 选择新地点和一种出行方式，分次推进游戏时间。 | 使用保存的实际耗时；未消耗足够时间时仍在路上；到达后位置正确，途中能聊天。 |
| P5-05 | 与空闲角色约在新地点见面，完成双方移动后开始故事。 | 角色没有瞬移；故事使用新场景，并能引用已有共同记忆。 |
| P5-06 | 结束新地点故事后聊天，再切换世界并返回。 | 新地点经历能进入原聊天；其他世界冻结规则正常；新地点和记忆保留。 |
| P5-07 | 离开新地点，正常切换页面或重新进入 APP，再查看地点和角色聊天。 | 新地点、已有消息和共同记忆仍可使用，角色会话不重复；这是正常业务连续性检查，不涉及备份恢复或迁移。 |
| P5-08 | 从包含动作和场景描写的新地点故事返回聊天，再触发一条主动消息。 | 普通回复和主动消息都恢复角色口吻与纯消息形式，不出现残留旁白、动作或内心独白；通知预览也一致。 |
| P5-09 | 在真实设备连续执行完整用户流程，并复测关闭 APP 后的通知。 | 各模块衔接正常；冻结、见面、记忆和通知没有互相矛盾；不以单独页面可用代替流程通过。 |

## 5. 最终验收交付物

- 可安装版本、构建标识及本次实际验证的设备和运行场景。
- 地点生成、路线和耗时、新地点故事的截图和录屏。
- 角色卡完整性、生成地点的路线数据、线上纯消息与线下故事边界的验证记录。
- 五阶段全部用例的实际结果，完整用户流程录屏，以及尚未解决的问题清单。

通过条件：新增地点可实际使用，全部已确认功能在完整流程中协同工作，线上保持自然的纯消息聊天。任何阶段尚未通过的必要用例都应继续标为未通过，不能仅以五份文档完成或版本可安装作为功能交付完成。
